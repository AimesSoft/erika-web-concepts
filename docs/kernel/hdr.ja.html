ハイダイナミックレンジ

HDR / EDR Output

プラットフォームによってネゴシエートされた liberika 出力エンコード: Apple EDR、Windows HDR10 PQ、Android、および Linux extended-linear scRGB。ネゴシエーションが失敗した場合は、SDR にフォールバックします。フォールバックの理由とカウント時間 ErikaOutputStatus 黙って降格させるのではなく、報告してください。

  • 出力モード 4 親切
  • アクティブコーディング 5 親切
  • フォールバックの理由 8 種（それ以外の場合） None ロールバックがないことを示します)

出力モード努力してください#

ホストが presenter を作成したとき ErikaPresenterConfig.output_mode ステートメントリクエスト:

モード値説明
Sdr0SDR出力を修正しました。
AppleEdr1Apple EDR、headroom によって拡張されました。
ExtendedLinear2extended-linear 出力 (Android / Linux scRGB パス)。
Auto3コンテンツと表面の機能に基づいた自動選択。

実際の効果的なエンコーディングは次の場所に記録されます。 ErikaOutputStatus.active_encoding：SdrSrgb、AppleEdr、AndroidExtendedLinearScRgb、Hdr10Pq、LinuxExtendedLinearScRgb。リクエスト モードとアクティブなエンコーディングは異なる場合がありますが、その違いはフォールバックです。

Headroom 交渉ヘッドルーム#

EDR パスと scRGB パスは、ディスプレイのピーク輝度に基づいてダイナミック レンジをネゴシエートします。ホスト用 set_output_headroom レンダラーがサーフェスの実際の機能に基づいて使用可能な値に収束できるかどうかを示すフラグを、必要な headroom に提供します。

ネゴシエーション中のステータス フィールド:

  • requested_headroom — ホスト要求値。
  • active_headroom / active_headroom_known — 現在の実効値と有効性。
  • headroom_updates — 実効値の変更の数。
  • extended_linear_frames — extended-linear エンコードで出力されるフレームの数。

ロールバックフォールバック#

フォールバック理由の列挙 ErikaOutputFallbackReason 含まれています None(ロールバックが発生しなかったことを示します) 合計 9 つの値があり、そのうち 8 つは実際のロールバックの理由です。

理由値意味
None0フォールバックはありません。
DisplayHdrUnsupported1モニターはHDRをサポートしていません。
HybridCompositionRequired2混合合成が必要です。
WgpuBackendNotVulkan3wgpu バックエンドは Vulkan ではありません。
Rgba16FloatSurfaceFormatUnavailable4RGBA16F はサーフェスではサポートされていません。
NativeWindowDataSpaceApiUnavailable5native window に data space API がありません。
ScrgbDataSpaceVerificationFailed6scRGB data space 検証に失敗しました。
SurfaceConfigureFailed7サーフェスの構成に失敗しました。
LegacyAppleEdrUnsupported8従来の Apple EDR パスは使用できません。

fallback_count ロールバックの累積数、data_space_failures ネゴシエーション失敗数 data space が個別に累積されます。ホストはこれら 2 つの項目を使用して、ターゲット デバイスの HDR サポートが安定しているかどうかを判断できます。

Android scRGB には、Vulkan、RGBA16F サーフェスと正しい native window data space が必要です。 Linux scRGB には、FP16 extended-linear WSI が必要です。通常のSDR面はtone mapping出力を使用します。

Tone Mapping および Dolby Vision#

0.2.0 以降、デフォルトで BT.2390 EETF が使用され、ピーク圧縮は IPT 色空間で完了します。 spline、BT.2446a、ST 2094、Mobius、Reinhard、clip などの演算子はオプションです。黒点とターゲットのコントラストもマッピングに参加します。

Dolby Vision RPU は、piecewise / MMR reshaping および非線形行列変換をサポートし、Profile 5 / 8 は BT.2020 / PQ として処理されます。 Profile 7 はベース レイヤとそのマッピングを使用しますが、エンハンスメント レイヤの残差はまだ合成に参加していません。 Dolby Vision 信号をディスプレイに透過的に送信するのではなく、ここでレンダリング変換が実行されます。

HDR10 ソフトウェア フレームは、フレームごとの輝度統計を使用してピークに設定でき、知覚色域マッピング LUT は CPU によってバックグラウンドで構築され、フレーム全体でキャッシュされます。 Apple EDR 出力はモニター headroom で更新されます。 P010 アップロードでは 10-bit の精度が維持されます。
