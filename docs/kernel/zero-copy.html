零拷贝导入

Zero-copy Import

硬件解码器的输出以原生纹理或 buffer 句柄的形式直接导入渲染器，中间不经过 CPU 拷贝。每条导入路径都有一一对应的回退：无法导入时走 CPU upload，帧计数如实反映两条路径的使用比例。

  • 导入路径 4 条
  • 回退 CPU upload
  • 计数 zero_copy / cpu_fallback

各平台导入路径取り込み経路#

平台解码输出导入目标机制
macOS / iOS / tvOSCVPixelBufferMTLTextureMetal 直接持有 pixel buffer 的纹理，按 iosurface 或共享内存零拷贝引用。
WindowsD3D11VA 纹理D3D11 纹理解码器纹理与渲染器纹理互操作，渲染 pass 直接采样解码输出。
AndroidMediaCodec SurfaceAHardwareBuffer → Vulkansurface 帧经 AHardwareBuffer 句柄导入 wgpu/Vulkan，映射为 VkImage。
HarmonyOSAVCodec SurfaceOHNativeBuffer → VulkanOHNativeBuffer 零拷贝导入，经 wgpu/Vulkan 呈现。

回退与计数フォールバック#

导入失败的帧退回 CPU upload：解码输出经 avcodec 拷贝到 CPU 侧内存，再作为普通纹理上传。渲染器不区分帧的来源，两条路径走同一套渲染管线。

回退的原因包括句柄获取失败、格式不兼容、显存分配失败等。帧计数将两条路径分开统计：

字段含义
zero_copy_video_frames零拷贝导入成功的帧数。
direct_zero_copy_video_frames直接引用解码输出的帧数（不复制）。
shared_handle_video_frames经共享句柄（AHardwareBuffer / OHNativeBuffer 等）导入的帧数。
cpu_video_frame_fallbacks退回 CPU upload 的帧数。
import_failures导入失败的次数，包含失败后成功回退的情况。

用 zero_copy_video_frames / (zero_copy_video_frames + cpu_video_frame_fallbacks) 可以得到一段时间内的零拷贝命中率，macos_native_demo --smoke-seconds 3 会在退出前打印这些计数器。

导入失败不回滚播放。 单帧导入失败只触发该帧的 CPU 回退，不中断播放。持续失败多见于显存不足或驱动异常，反映在 import_failures 的增长上。
