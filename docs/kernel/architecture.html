架构总览

Architecture

Erika 由 Rust 实现，从 demux、解码到 GPU 呈现、音频、字幕与弹幕均在内核内部完成。宿主提供渲染表面并发送播放命令，不参与渲染管线。

  • 核心 crate crates/erika
  • C ABI 层 crates/erika_capi
  • 内部线程 5
  • 后端 trait 3

仓库分层構成#

路径职责
crates/erika核心播放库。Player、Presenter、渲染后端、音频、字幕、弹幕。
crates/erika_capiC ABI 导出层。全部导出以 include/erika.h 为准。
crates/erika_ffmpeg_sysFFmpeg bindgen 绑定。
packages/erika_flutterFlutter 插件，覆盖 macOS / iOS / tvOS / Windows / Android / HarmonyOS。
examples/验证、冒烟与演示程序。macos_native_demo、windows_native_demo 为端到端示例。
xtask/原生依赖构建编排。deps plan / fetch / status / build。

模块划分モジュール#

crates/erika/src/ 下的模块按职责划分，平台相关代码以 #[cfg(target_os = …)] 门控，集中在 apple.rs、windows.rs、android.rs、ohos.rs 及其子目录。

模块职责
corePlayer、PlayerConfig、事件类型、RendererBackend trait。
playback播放状态机、音频主时钟、帧调度器、VideoDecodePreference。
presenterPresenterRuntime。串起 player、renderer、audio、overlay，由 render_tick 驱动。
ffmpegdemux、decode、resample、seek。DecoderBackend 五种后端的选择与配置。
audioAudioOutputBackend trait、f32 PCM ring buffer、音频时钟。
renderermetal（Apple）、d3d11（Windows）、wgpu（Android、HarmonyOS）后端；pipeline 做后端无关的色彩与 tone map 决策。
subtitleSRT / WebVTT / ASS 解析与 libass 渲染，嵌入与外挂字幕轨。
danmakuBilibili XML / JSON 解析、DFM+ 碰撞避让布局、glyph atlas 渲染。
overlay合成时间线，字幕与弹幕的播放窗口管理。
sourceMediaSource trait，file 与 HTTP range 两种实现。
trace / debug_hud诊断设施。环境变量开关与 HUD 覆盖层。

数据流データフロー#

播放链路从媒体源开始，到渲染表面结束：

playback data flow

MediaSource (file / HTTP range)
  → demux (ffmpeg)
  → decode (DecoderBackend: hardware / software)
  → frame queue (video / audio / subtitle)
  → PresenterRuntime::render_tick(host_time)
  → RenderFrameContext { media_time, overlay, danmaku, output_size }
  → RendererBackend::render_current_frame
  → surface (Metal / D3D11 / wgpu)

状态与事件走独立的 crossbeam channel。播放器状态变化、时长、轨道、缓冲、错误等信息发布到事件通道，宿主经 poll_event 或 Rust 侧的事件订阅消费。

时间基准。 音频输出是主时钟。视频呈现按 vsync 量化对齐音频时钟，细节见时钟与调度。

线程模型スレッド#

内核内部维护 5 个常驻线程，另有一部分平台音频输出跑在系统回调上下文（CoreAudio 回调、WASAPI render 线程）。

线程名职责
erika-playback命令循环。消费 PlaybackCommand，内联视频解码，管理状态机。
erika-demuxdemux 消费线程，向 playback 线程投递 bounded 包队列（容量 512）。
erika-danmaku弹幕 plan 生成。Mutex + Condvar 请求模型，结果经 unbounded channel 回传。
erika-upscaler-buildArtCNN 权重加载与后端构建（Metal 路径）。
erika-wasapi-renderWindows WASAPI 音频输出线程。

宿主线程与内核的边界由 C ABI 层约束：一个 handle 不提供内部同步，不得从多个线程并发调用。

三个入口エントリポイント#

Erika 暴露三组使用方式，按宿主语言和渲染所有权区分。

入口宿主渲染所有权说明
PlayerRust宿主拉取帧数据完整 Rust API。事件订阅 + 视频/音频/字幕帧订阅。
ErikaHandleC / Swift / Dart FFI宿主拉取帧数据pull 模型。宿主自行管理渲染循环。
ErikaPresenterHandleC / Swift / Dart FFI内核托管push 模型。宿主提供表面并每帧调用 render_tick。

三套入口共享同一套内部实现。C ABI 层每个导出函数用 catch_unwind 包裹，panic 映射为 ErikaStatus_Panic，不越过 FFI 边界。

后端抽象抽象化#

平台差异收敛在三个 trait 之后，使 presenter 与渲染循环保持平台无关。

  • RendererBackend（core.rs）— 表面附着与大小调整、render_current_frame、upload_player_frame、截图。Metal、D3D11、wgpu 三种实现。
  • AudioOutputBackend（audio.rs）— 配置、播放控制、push(PcmAudioFrame)、时钟快照。CoreAudio / AudioQueue / WASAPI / AAudio / OHAudio 实现。
  • DecoderBackend（ffmpeg.rs）— 软件、VideoToolbox、D3D11VA、MediaCodec、AVCodec 五种解码后端。

选择规则：RendererBackendPreference（平台原生或 wgpu 回退）决定渲染后端，VideoDecodePreference 按平台默认选择解码后端。
