Architecture overview

Architecture

liberika is implemented by Rust. From demux, decoding to GPU rendering, audio, subtitles and danmaku are all completed inside the kernel. The host provides the rendering surface and sends playback commands, and does not participate in the rendering pipeline.

  • Core crate crates/erika
  • C ABI layer crates/erika_capi
  • internal thread 5
  • Backend trait 3

data flowデータフロー#

The playback chain starts from the media source and ends at the rendering surface:

playback data flow

MediaSource (file / HTTP range)
  → demux (ffmpeg)
  → decode (DecoderBackend: hardware / software)
  → frame queue (video / audio / subtitle)
  → PresenterRuntime::render_tick(host_time)
  → RenderFrameContext { media_time, overlay, danmaku, output_size }
  → RendererBackend::render_current_frame
  → surface (Metal / D3D11 / wgpu)

The status and events are independent crossbeam channel. Player status changes, duration, track, buffering, errors and other information are published to the event channel, and the host poll_event Or event subscription consumption on the Rust side.

time base. The audio output is the master clock. Video rendering is quantized to align the audio clock by vsync, see details inClock and scheduling。

Threading modelスレッド#

The kernel maintains 5 resident threads internally, and some platform audio output runs in the system callback context (CoreAudio callback, WASAPI render thread).

Thread nameResponsibilities
erika-playbackCommand loop. consumption PlaybackCommand, inline video decoding, management state machine.
erika-demuxThe demux consumer thread delivers the bounded packet queue (capacity 512) to the playback thread.
erika-danmakuThe danmaku plan is generated. Mutex + Condvar requests the model, and the results are returned via unbounded channel.
erika-upscaler-buildArtCNN weight loading and backend construction (Metal path).
erika-wasapi-renderWindows WASAPI audio output thread.

The boundary between the host thread and the kernel is bounded by the C ABI layer: a handle provides no internal synchronization and may not be called concurrently from multiple threads.

three entrancesエントリポイント#

liberika exposes three groups of usages, differentiated by host language and rendering ownership.

entrancehostRender ownershipDescription
PlayerRustHost pulls frame dataComplete Rust API. Event subscription + video/audio/subtitle frame subscription.
ErikaHandleC / Swift / Dart FFIHost pulls frame datapull model. The host manages the rendering loop itself.
ErikaPresenterHandleC / Swift / Dart FFIKernel hostingpush model. The host provides the surface and calls it every frame render_tick。

The three sets of entrances share the same internal implementation. Each exported function of C ABI layer uses catch_unwind Package, panic maps to ErikaStatus_Panic, does not cross the FFI boundary.

backend abstractionabstraction#

Platform differences converge after three trait, making presenter and the render loop remain platform independent.

  • RendererBackend(core.rs)—Surface attachment and sizing,render_current_frame、upload_player_frame, screenshot. There are three implementations of Metal, D3D11, and wgpu.
  • AudioOutputBackend(audio.rs)—Configuration, playback control,push(PcmAudioFrame), clock snapshot. CoreAudio / AudioQueue / WASAPI / AAudio / OHAudio implementation.
  • DecoderBackend(ffmpeg.rs)—software, VideoToolbox, D3D11VA, MediaCodec, AVCodec five decoding backends.

Selection rules:RendererBackendPreference(Platform native or wgpu fallback) determines the rendering backend,VideoDecodePreference Decoding backend is selected by platform by default.

Browser backend · 0.3.0#

Web is an independent JavaScript Player interface: FFmpeg WASM reads and decapsulates in Worker, and the compressed package is handed over to WebCodecs, libass and Rust DFM engines process subtitles and danmaku, and then WebGL2 Synthesis; Web Audio provides output and playback clock. It does not use the native Presenter C ABI, nor does it include the desktop HDR or ArtCNN. Deployment and support scope seeWeb / WASM access。
