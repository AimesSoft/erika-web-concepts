字幕と弾幕

Subtitle & Danmaku

字幕トラックは、libass によってレンダリングされた SRT / WebVTT / ASS をサポートします。弾幕は、DFM+ 衝突回避レイアウトを使用して、Bilibili XML および JSON の 2 つの入力をサポートし、glyph atlas によって GPU 上に描画されます。どちらも、レンダー パイプラインのコンポジション pass 内のビデオでフレーム化されています。

  • 字幕のレンダリング libass
  • 弾幕レイアウト DFM+
  • 描く glyph atlas

字幕字幕#

字幕トラックは、埋め込みとプラグインの 2 つのソースに分かれています (ErikaTrackSource）。外部字幕 add_external_subtitle 追加、トラック id を返します。字幕トラック id は -1 で字幕を無効にします。外部テキスト字幕には文字セット検出とトランスコーディングが付属しており、GBK、Big5、Shift_JIS、UTF-16、UTF-8 パススルーをカバーし、信頼性の低い入力やバイナリ入力は控えめにフォールバックします。

レンダリングの統合は libass によって行われ、埋め込み Droid Sans Fallback はすべてのプラットフォームでメモリ内フォントとして登録され、システム フォント プロバイダーのないターゲット プラットフォームはデフォルトでこのファミリーを使用します。

スタイルの上書き

ホストは字幕スタイル全体をオーバーライドできます。カバレッジの粒度はビットによって制御されます。ErikaSubtitleStyle.override_mask ビットフラグ:

ロゴビットオーバーライド
ERIKA_SUBTITLE_OVERRIDE_FONT_SIZE_FIELDS2フォントサイズ
ERIKA_SUBTITLE_OVERRIDE_FONT_NAME3フォントファミリーとフォントファイル
ERIKA_SUBTITLE_OVERRIDE_COLORS4メインカラーとストロークカラー
ERIKA_SUBTITLE_OVERRIDE_ATTRIBUTES5太字、斜体、下線、取り消し線
ERIKA_SUBTITLE_OVERRIDE_BORDER6枠線のスタイルと幅
ERIKA_SUBTITLE_OVERRIDE_ALIGNMENT7整列
ERIKA_SUBTITLE_OVERRIDE_MARGINS8マージン
ERIKA_SUBTITLE_OVERRIDE_BLUR11ぼやけた

ERIKA_SUBTITLE_OVERRIDE_ALL 上記の組み合わせです。コンテナー ASS スクリプトは、ホストがフォント名オーバーライド ビットによる置換を強制しない限り、独自のフォントを保持します。

メモリーフォント

0.1.5 ではメモリ フォント レジストリが導入されています。ホストは、(ディスクに書き込むことなく) フォント データを登録し、フォントの faces をクエリし、順序付けされたフォールバック セットを選択し、フォント データを置換し、レジストリをクリアできます。レンダラーは、選択されたフォントの世代に従ってキャッシュを再構築します。選択されたコレクション内のフォントは、置換直後にアクティブな字幕トラックで有効になります。登録されているが選択されていないフォントのみは、レンダラーの再構築をトリガーしません。

弾幕カーテン#

弾幕入力は、Bilibili XML (ファイルまたは URL) および JSON (インライン文字列) です。 2 つの読み込みパス:

  • load_danmaku_file / load_danmaku_json — すべての弾幕を匿名のトラックに置き換えます。
  • add_danmaku_track_file / add_danmaku_track_json — 名前付きマルチトラック リストを作成します。各トラックは個別に開始、停止、オフセットできます。

軌道レベル offset_micros 単一トラックのタイムラインをオフセットします。グローバル オフセットはすべてのトラックに適用されます。レイアウトイン erika-danmaku スレッド内で生成された plan は、ビデオとの同期を保つために、generation および media time でゲートされます。

DFM+ レイアウト

弾幕レイアウトは、DFM+ 衝突回避エンジンによって完成されます。上下の 3 つのスクロール モードには、それぞれトラックの割り当て、密度制限、およびカバレッジ戦略があります。 glyph atlas を描画すると、グリフは一度に atlas にラスタライズされ、インスタンス化された頂点を使用してフレームごとに描画されます。

レイアウトパラメータ ErikaDanmakuConfig コントロール:

フィールド意味
font_size弾幕の論理フォント サイズは、デフォルトの弾幕フォント NipaPlay と一致しており、サーフェス上で scale ピクセルから glyph ピクセルに変換されます。
opacity / outline_width / shadow_*透明度、ストローク幅、影のオフセット、スタイル。
display_area弾幕が占めることができる表示領域の割合。

シールド・シージン set_danmaku_block_words_json 提供される、JSON 配列形式で、弾幕テキストを 1 つずつ照合します。

弾幕 JSON 契約仕様

load_danmaku_json と add_danmaku_track_json インライン JSON を受け入れます。入力ルート ノードは、次の 2 種類の構造をサポートします。

  • Item配列: [ { ... }, { ... } ]
  • パッケージングオブジェクト: 含まれています comments、danmaku または items オブジェクトの配列など { "comments": [ ... ] }。列ごとに分割したJSON Lines(JSONL)にも対応します。

各弾幕 item でサポートされているフィールドは次のとおりです (互換性のあるエイリアスは括弧内にあります)。

フィールド名種類デフォルト値説明
content
(text, c)		String—弾幕テキスト。欠落しているエントリ、または空白文字のみが含まれているエントリは、自動的にスキップされます。
time
(t)		Number / String0.0弾幕表示時間 (秒)、浮動小数点秒をサポート (例: 12.45）。
type
(mode, y)		String / Number"scroll"弾幕タイプ:scroll / 1(スクロール)、bottom / 4(底部固定)、top / 5(上部固定)、reverse / 6(逆スクロール)、special / 7(高度な特殊。現在の解析後にレイアウトのレンダリングを開始しません)。数値フィールドも使用可能 type_code / mode_code。
color
(r)		Number / String白弾幕カラー: 10 進数の RGB 整数 (例: 16777215)、完了 #RRGGBB 16 進数の文字列 (例: "#FFFFFF") または CSS rgb(r,g,b)。注: 使用しないでください #FFF およびその他の 3 桁の略語 (これらは直接解析されて 0x000FFF）。
font_size
(fontSize, size, s)		Number / String25.0ソース参照フォント サイズ (ポイント)。最終的にレンダリングされるフォント サイズも、グローバル構成とサーフェス scale に応じてスケーリングされます。
opacity
(alpha, a)		Number / String1.0カスタムの不透明度 (0.0 ~ 1.0）。
is_me
(isMe, self, mine)		Boolean / Numberfalse現在のユーザーに対する自発的な弾幕であるかどうか (アンチスタック ポリシーによるフィルタリングを避けるためにレイアウトを優先します)。
idu64 / String順次割り当てビジネスID。サポート u64 範囲内の符号なし整数または 10 進数文字列。0 提供されないものとして扱います。

分析と行動規則:

  • id 省略可能: 省略された場合、0、不正な値、または範囲外の場合、liberika には入力全体の自然な位置に従って番号が割り当てられます。
  • 正確な u64 分析: サポート 0 到着 18446744073709551615（u64::MAX)、範囲内の符号なし整数または 10 進数文字列は、JS/JSON 倍精度浮動小数点精度の切り捨てを防ぐために、解析中に浮動小数点変換を受けません。
  • ビジネス ID はレイアウト ID から切り離されています。 ビジネス ID では、複数のトラックをマージするときに重複またはクロスオリジンの競合が許可されます。発信者スプライスしないでください track ID、また植字を一意にするために特別な ID を合成する必要はありません。
  • クロススライディング ウィンドウの連続性は次のことを保証します。 弾幕セッションは、マルチトラックのマージ後に内部レイアウト ID を現在のコンテンツ バージョンに個別に割り当てます。同じ連続セッション内で、連続タイム スライディング ウィンドウは、過去のアドミッションと軌道割り当ての決定、および外部コミットメントを厳密に継承します。「スライディング ウィンドウが更新された後、弾幕は表示されず、途中で軌道が変更されません。」(viewportのサイズ変更、タイムラインコンテンツの変更、レイアウト構成の調整を除く)。
  • フォールトトレランスメカニズム: ルート ノードの形式が正しくない場合は、直接失敗が返されます。単一の item テキストが欠落しているか空白の場合、バッチ解析全体を中断することなくスキップされます。不正なオプションフィールドはデフォルト値に戻ります。未知の事業分野（ cid、danmakuId) は無視しても問題ありません。

スーパーサンプリングのデフォルト · 0.3.0#

ネイティブと Web の両方のバックエンド字幕と弾幕スーパーサンプリングがデフォルトでオンになっており、これによりフォントの明瞭さが向上し、ビデオ解像度を上げることなく論理表示サイズが維持されます。両方とも独立して構成されます。 Webは利用可能です configureSubtitles({ supersampling: false }) そして configureDanmaku({ supersampling: false }) それぞれ閉じます。

一時停止ジャンプ、長い字幕スパン seek、および一時停止トラックのカットでは、現在の字幕が再計算されます。システム フォント フォールバックは、ゼロコピー上書きチェックと有界 LRU キャッシュを介してメモリを制御し、有効なグリフを保持します。
