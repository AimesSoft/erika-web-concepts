Zero copy import

Zero-copy Import

The output of the hardware decoder is directly imported into the renderer in the form of a native texture or buffer handle, without a CPU copy in between. Each import path has a one-to-one fallback: CPU upload when import cannot be performed, and the frame count truly reflects the usage ratio of the two paths.

Rollback and countingフォールバック#

Frames that failed to import are returned to CPU upload: decoded output avcodec Copy it to the CPU side memory, and then upload it as a normal texture. The renderer does not distinguish the source of the frame, and the two paths follow the same set of rendering pipelines.

Reasons for rollback include handle acquisition failure, format incompatibility, video memory allocation failure, etc. Frame counting separates the two paths:

Fieldmeaning
zero_copy_video_framesThe number of frames for successful zero-copy import.
direct_zero_copy_video_framesDirectly reference the frame number of the decoded output (no copying).
shared_handle_video_framesNumber of frames imported via shared handle (AHardwareBuffer / OHNativeBuffer, etc.).
cpu_video_frame_fallbacksReturn the number of frames CPU upload.
import_failuresThe number of import failures, including successful rollback after failure.

use zero_copy_video_frames / (zero_copy_video_frames + cpu_video_frame_fallbacks) You can get a zero copy hit rate within a period of time,windows_native_demo --smoke-seconds 3 will print these counters (macOS's macos_native_demo smoke mode only sets the running time and does not print the counter).

Playback will not roll back if the import fails. Failure to import a single frame only triggers the CPU rollback of that frame without interrupting playback. Continuous failure is mostly caused by insufficient video memory or driver abnormality, which is reflected in import_failures on the growth.

Linux GPU import#

Linux VA-API can be passed FFmpeg AV_HWFRAME_MAP_DIRECT Map NV12 / P010 to the Vulkan image, which is directly sampled by wgpu; this experimental path requires compatible equipment, external video memory, semaphore and other capabilities.

Normal NVDEC / WSL OpenGL paths use CPU plane transfer; optional WSL D3D12 paths use GPU replication. Wayland native video layer can reduce Flutter RGBA readback, and whether the decoded frame has zero copies are two different things. The build steps are included in Linux access。
