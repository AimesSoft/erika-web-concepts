Zero-copy import

Zero-copy Import

The hardware decoder's output is imported directly into the renderer as a native texture or buffer handle, with no CPU copy in between. Each import path has a matching fallback: when a frame cannot be imported, it goes through CPU upload instead, and the frame counters accurately reflect how often each path is used.

  • Fallback CPU upload
  • Counters zero_copy / cpu_fallback

Fallback and countersフォールバック#

A frame that fails to import falls back to CPU upload: the decoded output is copied through avcodec into CPU-side memory and then uploaded as an ordinary texture. The renderer does not distinguish where a frame came from, and both paths use the same rendering pipeline.

Fallbacks happen for reasons such as failing to obtain a handle, an incompatible format, or a failed video memory allocation. The frame counters track the two paths separately:

FieldDescription
zero_copy_video_framesNumber of frames imported successfully with zero copy.
direct_zero_copy_video_framesNumber of frames that reference the decoder output directly (no copy).
shared_handle_video_framesNumber of frames imported through a shared handle (AHardwareBuffer, OHNativeBuffer, and so on).
cpu_video_frame_fallbacksNumber of frames that fell back to CPU upload.
import_failuresNumber of import failures, including those where the fallback then succeeded.

zero_copy_video_frames / (zero_copy_video_frames + cpu_video_frame_fallbacks) gives the zero-copy hit rate over a period of time. windows_native_demo --smoke-seconds 3 prints these counters before it exits (the smoke mode of macOS's macos_native_demo only sets the run time and does not print the counters).

A failed import does not interrupt playback. When a single frame fails to import, only that frame falls back to the CPU path and playback continues. Persistent failures are usually caused by insufficient video memory or a driver fault, and show up as growth in import_failures.

Linux GPU import#

On Linux, VA-API can map NV12 / P010 to a Vulkan image through FFmpeg's AV_HWFRAME_MAP_DIRECT, and wgpu samples it directly. This experimental path requires a compatible device with external memory, semaphores, and related capabilities.

The regular NVDEC and WSL OpenGL paths pass planes through the CPU; the optional WSL D3D12 path uses a GPU copy. A native Wayland video layer can reduce Flutter RGBA readback, but that is a separate matter from whether decoded frames are zero-copy. For build steps, see Linux integration.
