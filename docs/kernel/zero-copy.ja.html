ゼロコピーインポート

Zero-copy Import

ハードウェア デコーダーの出力は、間に CPU コピーを介さずに、ネイティブ テクスチャまたは buffer ハンドルの形式でレンダラーに直接インポートされます。各インポート パスには、インポートを実行できない場合の CPU upload という 1 対 1 のフォールバックがあり、フレーム数は 2 つのパスの使用率を正確に反映します。

  • ロールバック CPU upload
  • 数える zero_copy / cpu_fallback

ロールバックとカウントフォールバック#

インポートに失敗したフレームは CPU upload: デコードされた出力に返されます。 avcodec CPU側のメモリにコピーして、通常のテクスチャとしてアップロードします。レンダラーはフレームのソースを区別せず、2 つのパスは同じレンダリング パイプラインのセットに従います。

ロールバックの理由には、ハンドル取得の失敗、フォーマットの非互換性、ビデオ メモリ割り当ての失敗などが含まれます。フレーム カウントにより、次の 2 つのパスが分離されます。

フィールド意味
zero_copy_video_framesゼロコピーインポートが成功したフレーム数。
direct_zero_copy_video_framesデコードされた出力のフレーム番号を直接参照します (コピーなし)。
shared_handle_video_frames共有ハンドル (AHardwareBuffer / OHNativeBuffer など) を介してインポートされたフレームの数。
cpu_video_frame_fallbacksフレーム数 CPU upload を返します。
import_failures失敗後の成功したロールバックを含む、インポートの失敗の数。

使う zero_copy_video_frames / (zero_copy_video_frames + cpu_video_frame_fallbacks) 一定期間内にコピーヒット率がゼロになることもありますが、windows_native_demo --smoke-seconds 3 これらのカウンタ (macOS の macos_native_demo smoke モードでは実行時間のみを設定し、カウンターは出力しません)。

インポートが失敗した場合、再生はロールバックされません。 単一フレームのインポートに失敗した場合、再生を中断することなく、そのフレームの CPU ロールバックのみがトリガーされます。継続的な障害は、主にビデオ メモリの不足またはドライバの異常によって発生し、これが反映されます。 import_failures 成長について。

Linux GPU インポート#

Linux VA-API は合格可能 FFmpeg AV_HWFRAME_MAP_DIRECT NV12 / P010 を Vulkan 画像にマッピングします。これは、wgpu によって直接サンプリングされます。この実験的なパスには、互換性のある機器、外部ビデオ メモリ、セマフォ、その他の機能が必要です。

通常の NVDEC / WSL OpenGL パスは CPU プレーン転送を使用します。オプションの WSL D3D12 パスは、GPU レプリケーションを使用します。 Wayland ネイティブ ビデオ レイヤーは Flutter RGBA リードバックを削減できることと、デコードされたフレームのコピーがゼロかどうかは別のことです。ビルド手順は以下に含まれています Linux アクセス。
