Render Pipeline

The video, subtitles and danmaku are sampled, color converted, tone mapping, zoomed and synthesized in the same pass picture, render pass on the screen at once. pass Picture by pipeline::build_graph Constructed conditionally on the color state of the source and destination.

  • pass type 11 kind
  • backend Metal / D3D11 / wgpu
  • Geometry aspect_fit centered

pass diagramパスグラフ#

RenderPassKind All 11 types of pass are defined. When rendering a frame,build_graph The transformations from the import frame to the output are combined sequentially, and pass that do not meet the conditions are skipped:

passResponsibilities
ImportFrameDecoded frames are imported as GPU texture (zero copy or CPU upload).
NeuralUpscaleArtCNN Brightness 2× Super Resolution, only inserted when enabled and supported by the backend.
PlaneSamplingYCbCr planar sampling, uv upsampling and chroma reconstruction.
ChromaReconstructionChroma plane reconstruction.
TransferDecodeTransfer function decoding to restore linear light from the encoded format.
GamutMapGamut mapping, inserting when the source and target primary colors are different.
ToneMaptone mapping, inserted when the source is HDR and the peak exceeds the target by about 1.05 times.
ScaleScale to output size.
OverlayCompositeThe synthesis of subtitle layer (internal kernel overlay) and danmaku.
DitherJitter when output bit depth is reduced.
OutputTransformEncode to output format (SDR/EDR/HDR10 PQ/scRGB).

The two conditional insertion rules come from SourceColorState with TargetColorState Comparison of: tone map is only inserted if the source is HDR and the peak exceeds the target by about 5%, gamut mapping is only inserted if the source and target primary colors are different. SDR content is directly sampled and output transformed on the SDR target.

Backend implementationバックエンド#

backendplatformDescription
MetalmacOS / iOS / tvOSNative implementation. YCbCr sampling, color conversion, tone mapping, overlay synthesis. ArtCNN goes simdgroup matrix.
Direct3D 11WindowsNative implementation. D3D11VA texture interop, HDR10 output, overlay composition.
wgpuAndroid / HarmonyOSVulkan backend, GLES with recovery path available. HarmonyOS presented by OHNativeWindow.

The rendering backend is determined by the presenter configuration, regardless of the surface attachment method. Color decisions are unified pipeline module, the three backends share the same set of pass graph descriptions.

Composition and Geometrysynthesis#

Subtitles and danmaku in OverlayComposite Synthesized in pass. Compositing takes place within the video viewport: bullet posts and subtitles are positioned relative to the video content, following the video's aspect-fit geometry.

Video content starts with aspect_fit Centered within the output surface, the letterbox area is filled with the clear screen color (currently uniformly black on the backend). The synthesis sequence is video, subtitles, and danmaku.

The rendering chain of HDR content and the screenshot chain share the same pass image; the screenshot is rendered to an off-screen target with the same pixel format as the surface, and is converted to RGBA8 when read back (the HDR value is clamped to the SDR range). The screenshots only combine video and subtitles, excluding danmaku and debug HUD.
