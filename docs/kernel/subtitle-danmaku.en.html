Subtitles and danmaku

Subtitle & Danmaku

The subtitle track supports SRT / WebVTT / ASS, rendered by libass; the danmaku supports two inputs: Bilibili XML and JSON, using DFM+ collision avoidance layout, and is drawn on GPU by glyph atlas. Both are framed with video in the render pipeline's composition pass.

  • subtitle rendering libass
  • Danmaku layout DFM+
  • draw glyph atlas

subtitlessubtitles#

Subtitle tracks are divided into two sources: embedded and plug-in (ErikaTrackSource). External subtitles add_external_subtitle Add, return track id; subtitle track id is -1 to disable subtitles. External text subtitles come with character set detection and transcoding, covering GBK, Big5, Shift_JIS, UTF-16, UTF-8 pass-through, and low confidence or binary input will fall back conservatively.

Rendering unification is done by libass, the embedded Droid Sans Fallback is registered as an in-memory font on all platforms, and target platforms without a system font provider use this family by default.

Memory font

0.1.5 introduces memory font registry. The host can register font data (without writing to disk), query the faces of the font, select an ordered fallback set, replace font data and clear the registry. The renderer rebuilds the cache according to the selected generation of the font: fonts in the selected collection will take effect on the active subtitle track immediately after replacement; only registered but unselected fonts will not trigger renderer reconstruction.

Danmakucurtain#

The danmaku input is Bilibili XML (file or URL) and JSON (inline string). Two loading paths:

  • load_danmaku_file / load_danmaku_json — Replace all danmaku with an anonymous track.
  • add_danmaku_track_file / add_danmaku_track_json — Create a named multi-track list, each track can be started, stopped and offset independently.

Orbital level offset_micros Offset the timeline of a single track, global offset applies to all tracks. Layout in erika-danmaku Generated in the thread, plan is gated with generation and media time to keep synchronized with the video.

DFM+ layout

The danmaku layout is completed by the DFM+ collision avoidance engine: the three modes of scrolling, top and bottom have respective track allocation, density restrictions and coverage strategies. Draw glyph atlas, the glyphs are rasterized into atlas at once, and then drawn frame by frame with instanced vertices.

Danmaku JSON Contract Specifications

load_danmaku_json with add_danmaku_track_json Accepts inline JSON. The input root node supports two types of structures:

  • Item array: [ { ... }, { ... } ]
  • Packaging object: contains comments、danmaku or items Array of objects, for example { "comments": [ ... ] }. Also compatible with JSON Lines (JSONL) split by rows.

Analysis and behavioral convention:

  • id Can be omitted: When omitted, 0, illegal, or out of bounds, liberika is assigned numbers according to their natural position in the entire input.
  • precise u64 Analysis: support 0 Arrive 18446744073709551615（u64::MAX), unsigned integers or decimal strings within the range will not undergo floating point conversion during parsing to prevent JS/JSON double-precision floating-point precision truncation.
  • Business ID is decoupled from layout identity: Business ID allows duplication or cross-origin conflicts when merging multiple tracks. callerShould not be spliced track ID, alsoThere is no need to synthesize special ID for typesetting uniqueness。
  • Cross-sliding window continuity guarantees: Danmaku sessions independently assign internal layout identities to the current content version after multi-track merging. In the same continuous session, the continuous time sliding window will strictly inherit the historical admission and orbit allocation decisions, and the external commitment"The danmaku will not appear or change tracks halfway after the sliding window is refreshed"(Except for viewport size changes, timeline content changes, or layout configuration adjustments).
  • Fault tolerance mechanism: If the root node format is incorrect, a failure will be returned directly; if a single item text is missing or blank, it will be skipped without interrupting the entire batch parsing; illegal optional fields will fall back to default values; unknown business fields (such as cid、danmakuId) is safely ignored.

Supersampling default · 0.3.0#

Both native and Web backend subtitles and danmaku supersampling are turned on by default, which improves font clarity and maintains the logical display size without increasing video resolution. Both are configured independently; Web is available configureSubtitles({ supersampling: false }) and configureDanmaku({ supersampling: false }) Close respectively.

Pause jump, long subtitle span seek and pause track cutting will recalculate the current subtitle. System font fallback controls memory via zero-copy overwrite checking and a bounded LRU cache, preserving valid glyphs.
