高动态范围

HDR / EDR Output

Erika 按平台协商输出编码：Apple EDR、Windows HDR10 PQ、Android extended-linear scRGB。协商失败时回退 SDR，回退原因与计数经 ErikaOutputStatus 上报，不静默降级。

  • 输出模式 4 种
  • 活跃编码 4 种
  • 回退原因 8 种

输出模式出力モード#

宿主在创建 presenter 时经 ErikaPresenterConfig.output_mode 声明请求：

模式值说明
Sdr0固定 SDR 输出。
AppleEdr1Apple EDR，按 headroom 扩展。
ExtendedLinear2extended-linear 输出（Android scRGB 路径）。
Auto3按内容与表面能力自动选择。

实际生效的编码记录在 ErikaOutputStatus.active_encoding：SdrSrgb、AppleEdr、AndroidExtendedLinearScRgb、Hdr10Pq。请求模式与活跃编码可以不同，差异即回退。

Headroom 协商ヘッドルーム#

EDR 与 scRGB 路径按显示器的峰值亮度协商动态范围。宿主用 set_output_headroom 提供期望 headroom 与是否已知的标志，渲染器按表面的实际能力收敛到可用值。

协商过程中的状态字段：

  • requested_headroom — 宿主请求值。
  • active_headroom / active_headroom_known — 当前生效值及有效性。
  • headroom_updates — 生效值变更次数。
  • extended_linear_frames — 以 extended-linear 编码输出的帧数。

回退フォールバック#

回退原因枚举 ErikaOutputFallbackReason 覆盖 8 种情况：

原因值含义
None0无回退。
DisplayHdrUnsupported1显示器不支持 HDR。
HybridCompositionRequired2需要混合合成。
WgpuBackendNotVulkan3wgpu 后端不是 Vulkan。
Rgba16FloatSurfaceFormatUnavailable4表面不支持 RGBA16F。
NativeWindowDataSpaceApiUnavailable5native window 缺少 data space API。
ScrgbDataSpaceVerificationFailed6scRGB data space 校验失败。
SurfaceConfigureFailed7表面配置失败。
LegacyAppleEdrUnsupported8旧版 Apple EDR 路径不可用。

fallback_count 累计回退次数，data_space_failures 单独累计 data space 协商失败次数。宿主可以用这两项判断目标设备的 HDR 支持是否稳定。

Android extended-linear 的验证状态。 Android 的 FP16 extended-linear scRGB 输出在当前实现中已验证 SDR 播放与显式 SDR 回退。在 API 35 真机以 Rgba16Float + SCRGB_LINEAR 通过完整验收前，不应将 Android extended-linear 标记为真机已验证。

HDR 统计統計#

字段含义
hdr_source_framesHDR 源内容的帧数。
hdr10_output_frames以 HDR10 PQ 输出的帧数。
sdr_tonemap_framesHDR 源经 tone map 到 SDR 输出的帧数。
hdr10_metadata_updatesHDR10 元数据更新次数。
hdr10_metadata_failures元数据生成失败次数。
hdr10_output_failuresHDR10 输出失败次数。
hdr10_output_active当前是否以 HDR10 输出。

HDR 内容的 tone mapping 与输出变换在渲染管线内完成，见渲染管线。
