Neural upscaling

Neural Upscaling

ArtCNN is a 2× luma neural upscaling model for anime content. It processes only the luma channel, and its output joins the rendering pipeline as the NeuralUpscale pass. When no backend is available, the kernel keeps the native luma sampling and explicitly reports the Inactive status.

  • Model ArtCNN C4
  • Scale factor Luma ×2
  • Execution Metal / wgpu

Models and modesモデル#

The model weights are embedded in the crate (crates/erika/assets/artcnn) and packaged at compile time, so nothing is read from the file system at runtime. Weights come in two precisions, F16 and F32, which correspond to two request modes:

ModeValueDescription
Off0Turns upscaling off and uses native luma sampling.
ArtCnnC4F161Half-precision weights, for the Metal simdgroup matrix path.
ArtCnnC4F322Single-precision weights, for the wgpu compute path.

Execution paths実行経路#

The two compute implementations share one model description, and the weight format matches the request mode:

  • Metal(macOS / iOS / tvOS) — simdgroup matrix convolution. The weights are built in the background on the erika-upscaler-build thread; once the build finishes, the path joins the pipeline with the SimdgroupMatrix status.
  • wgpu compute(Android / HarmonyOS) — Tiled compute operators, F32 path.

The remaining rendering backend (D3D11) has no ArtCNN executor. When upscaling is requested there, native luma sampling is kept and active_backend reports Inactive, so the host can tell that the platform does not support upscaling.

Backend statusDescription
OffNot requested.
InactiveRequested, but no backend is available; native sampling is kept.
BuildingWeights are being built and the path has not yet joined the pipeline.
ScalarScalar execution path.
SimdgroupMatrixsimdgroup matrix execution path.

Pipeline integrationパイプライン#

Upscaling is inserted into the pass graph as the NeuralUpscale pass, between import and sampling. The model enlarges the luma channel by 2×, and the chroma channels are scaled conventionally. The later tone mapping, compositing, and output transform passes are unchanged.

The encode time and GPU time of each frame are recorded in last_encode_micros and last_gpu_micros. An execution failure increments fallback_count and temporarily falls back to native sampling; the kernel retries on the next frame.
