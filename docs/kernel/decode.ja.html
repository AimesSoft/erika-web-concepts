ハードウェアデコード

Decoding

デコードは一律FFmpeg avcodec インターフェース、経由 DecoderBackend ソフトウェアまたはハードウェア バックエンドを選択します。ハードウェア パスが使用できない場合は、ソフトウェア ソリューションにフォールバックし、 VideoDecoderChanged イベントを主催者に報告します。

  • バックエンド 7 親切
  • ハードウェア 6 / ソフトウェア 1
  • スイッチイベント VideoDecoderChanged

デコードバックエンドデコーダ#

バックエンドプラットフォーム説明
Cuda / NVDECLinux / NVIDIACUDAビデオデコードデバイスを使用してください。
VaapiLinux / Intel、AMDVA-API render device を使用します。
SoftwareすべてFFmpeg ソフト ソリューション、あらゆるプラットフォームのフォールバック ターゲット。
VideoToolboxmacOS / iOS / tvOSApple ハードウェア デコード。
D3d11vaWindowsDirect3D 11 ビデオ アクセラレーション。
MediaCodecAndroidsurface モードがメイン モードであり、ByteBuffer モードにフォールバックできません。

プラットフォームのデフォルトの選択は次のように行われます。 VideoDecodePreference 決定: Apple のデフォルトは VideoToolbox、Windows のデフォルトは D3D11VA、Android のデフォルトは MediaCodec、HarmonyOS のデフォルトは AVCodec、Linux のデフォルトは CUDA / NVDEC、次に VA-API です。他のプラットフォームではソフトウェア デコードが使用されます。

ハードウェアパスハードウェア経路#

ハードウェア バックエンドの選択は次の場所で行われます。 open_raw: バックエンドを押して、codec を選択します。 avcodec_get_hw_config ハードウェア構成を問い合わせてから使用します av_hwdevice_ctx_create デバイスコンテキストを作成します。デバイスの作成に失敗すると、フォールバック チェーンに沿ってソフトウェア デコードにフォールバックします。

MediaCodec はその中で最も特別なパスです。 surface モードのデコーダー バインディング AVMediaCodecDeviceContext.native_window、設定します ndk_codec=1、delay_flush=1、erika_nonblocking=1 3 つのオプション。 surface の作成またはバインドに失敗すると、再生スレッドは ByteBuffer モードでデコーダを再構築し、再起動します。プロセス全体がホストに一度だけ表示されます VideoDecoderChanged イベント。

フォールバックは明示的です。 すべてのバックエンド スイッチで公開する VideoDecoderChanged イベント。ホストはこれを使用して、診断インターフェイスを更新したり、ログを更新したりできます。統計フィールド hardware_video_frames と software_video_frames 2 つのパスそれぞれのデコードされたフレームの数を累積します。

フレームキューフレームキュー#

デコードされた出力は境界付きキューに入り、再生スレッドはレンダリング側キューから切り離されます。キューの深さは次の場所で確認できます。 PlayerConfig 中程度の調整:

キューデフォルトの容量設定フィールド
ビデオフレーム3video_frame_queue_capacity
オーディオフレーム192audio_frame_queue_capacity
字幕フレーム16subtitle_frame_queue_capacity

キューがいっぱいになると新しいフレームが破棄されます。統計フィールド video_frame_backpressure_drops 破棄されたビデオ フレームの累積数。オーディオ フレーム キューはオーディオ クロックによって消費され、容量は次のように構成されます。 PlayerConfig.audio_frame_queue_capacity 決める(AudioSyncConfig 同期パラメータのみが含まれ、容量は含まれません)。

ソフトウェアデコードフォールバック#

0.2.1 WMV / WMA ソフトウェア デコードを完了し、8-bit および 10-bit AV1 から dav1d をサポートします。ハード デコードが利用できない場合、またはビデオ形式がデバイスでサポートされていない場合、ソフトウェア フレームは同じレンダリング パイプラインに入ります。 Windows はソフトウェア フレームのアップロードもサポートしています。

ソフトウェア デコード スレッド · 0.3.0#

ソフトウェア ビデオ デコードでは、デフォルトでフレーム/スライスのマルチスレッドが有効になり、スレッドの数はエンコーダーとランタイム環境に基づいて FFmpeg によって選択されます。設定 ERIKA_VIDEO_DECODE_THREADS=1 シングルスレッドを復元します。純粋なソフトウェアパスをテストする場合は両方を使用してください ERIKA_HWDEC=software。

ハード復号化バックエンドが内部的にソフトウェア ピクセル フォーマットに戻ると、診断と VideoDecoderChanged 実際のデコード パス、フォールバック理由、およびカウントがレポートされますが、実際のハード デコードは、要求されたバックエンドだけでは判断できません。
