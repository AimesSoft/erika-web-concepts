レンダリングパイプライン

Render Pipeline

ビデオ、字幕、弾幕がサンプリングされ、カラー変換され、tone mapping ズームされ、画面上の同じ pass 画像、render pass に同時に合成されます。 pass 画像提供者 pipeline::build_graph ソースとデスティネーションのカラー状態に基づいて条件付きで構築されます。

  • pass型 11 親切
  • バックエンド Metal / D3D11 / wgpu
  • ジオメトリ aspect_fit中心

pass図パスグラフ#

RenderPassKind pass の 11 種類がすべて定義されています。フレームをレンダリングするとき、build_graph インポート フレームから出力への変換は順番に結合され、条件を満たさない pass はスキップされます。

pass責任
ImportFrameデコードされたフレームは、GPU テクスチャ (ゼロ コピーまたは CPU upload) としてインポートされます。
NeuralUpscaleArtCNN 輝度 2 倍の超解像度。バックエンドで有効かつサポートされている場合にのみ挿入されます。
PlaneSamplingYCbCr 平面サンプリング、uv アップサンプリング、およびクロマ再構築。
ChromaReconstructionクロマプレーンの再構成。
TransferDecode伝達関数をデコードして、エンコードされた形式から線形光を復元します。
GamutMap色域マッピング。ソースとターゲットの原色が異なる場合に挿入します。
ToneMaptone mapping。ソースが HDR で、ピークがターゲットを約 1.05 倍超える場合に挿入されます。
Scale出力サイズに合わせて拡大縮小します。
OverlayComposite字幕レイヤー（内部カーネルoverlay）と弾幕の合成。
Dither出力ビット深度が減少した場合のジッター。
OutputTransform出力形式 (SDR/EDR/HDR10 PQ/scRGB) にエンコードします。

2 つの条件付き挿入ルールは次のとおりです。 SourceColorState と TargetColorState 比較: tone map は、ソースが HDR で、ピークがターゲットを約 5% 超えている場合にのみ挿入され、色域マッピングは、ソースとターゲットの原色が異なる場合にのみ挿入されます。 SDR コンテンツは直接サンプリングされ、SDR ターゲット上で出力変換されます。

バックエンドの実装バックエンド#

バックエンドプラットフォーム説明
MetalmacOS / iOS / tvOSネイティブ実装。 YCbCr サンプリング、色変換、tone mapping、overlay 合成。 ArtCNN は simdgroup matrix になります。
Direct3D 11Windowsネイティブ実装。 D3D11VA テクスチャ相互運用、HDR10 出力、overlay コンポジション。
wgpuAndroid / HarmonyOSVulkan バックエンド、リカバリ パスが利用可能な GLES。 OHNativeWindowが贈るHarmonyOS。

レンダリング バックエンドは、サーフェス アタッチメント方法に関係なく、presenter 構成によって決定されます。色の決定が統一される pipeline モジュールでは、3 つのバックエンドが同じ pass グラフ記述のセットを共有します。

構成と幾何学合成#

字幕と弾幕 OverlayComposite passで合成しました。合成はビデオ ビューポート内で行われます。箇条書きと字幕は、ビデオの aspect-fit ジオメトリに従って、ビデオ コンテンツに対して相対的に配置されます。

動画コンテンツは以下から始まります aspect_fit 出力サーフェス内の中心にある letterbox 領域は、クリアなスクリーン カラー (現在バックエンドでは均一に黒) で塗りつぶされます。合成シーケンスはビデオ、字幕、弾幕です。

HDR コンテンツのレンダリング チェーンとスクリーンショット チェーンは、同じ pass 画像を共有します。スクリーンショットは、サーフェスと同じピクセル形式でオフスクリーン ターゲットにレンダリングされ、読み戻されるときに RGBA8 に変換されます (HDR 値は SDR 範囲にクランプされます)。スクリーンショットは、弾幕と debug HUD を除いて、ビデオと字幕のみを組み合わせています。
