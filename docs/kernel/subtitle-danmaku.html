字幕与弹幕

Subtitle & Danmaku

字幕轨支持 SRT / WebVTT / ASS，由 libass 渲染；弹幕支持 Bilibili XML 与 JSON 两种输入，走 DFM+ 碰撞避让布局，经 glyph atlas 在 GPU 上绘制。两者都在渲染管线的合成 pass 中与视频合屏。

  • 字幕渲染 libass
  • 弹幕布局 DFM+
  • 绘制 glyph atlas

字幕字幕#

字幕轨分嵌入与外挂两种来源（ErikaTrackSource）。外挂字幕经 add_external_subtitle 添加，返回轨道 id；字幕轨 id 为 -1 表示禁用字幕。外部文本字幕自带字符集检测与转码，覆盖 GBK、Big5、Shift_JIS、UTF-16，UTF-8 直通，低置信度或二进制输入走保守回退。

渲染统一由 libass 完成，内嵌的 Droid Sans Fallback 在所有平台上注册为内存字体，无系统字体提供者的目标平台默认使用该家族。

样式覆盖

宿主可以整体覆盖字幕样式。覆盖粒度按位控制，ErikaSubtitleStyle.override_mask 的位标志：

标志位覆盖项
ERIKA_SUBTITLE_OVERRIDE_FONT_SIZE_FIELDS2字号
ERIKA_SUBTITLE_OVERRIDE_FONT_NAME3字体族与字体文件
ERIKA_SUBTITLE_OVERRIDE_COLORS4主色与描边色
ERIKA_SUBTITLE_OVERRIDE_ATTRIBUTES5粗体、斜体、下划线、删除线
ERIKA_SUBTITLE_OVERRIDE_BORDER6边框样式与宽度
ERIKA_SUBTITLE_OVERRIDE_ALIGNMENT7对齐
ERIKA_SUBTITLE_OVERRIDE_MARGINS8边距
ERIKA_SUBTITLE_OVERRIDE_BLUR11模糊

ERIKA_SUBTITLE_OVERRIDE_ALL 是以上各位的组合。容器 ASS 脚本保留自己的字体，除非宿主通过字体名覆盖位强制替换。

内存字体

0.1.5 引入内存字体注册表。宿主可以注册字体数据（不写盘）、查询字体的 faces、选择有序回退集合、替换字体数据并清空注册表。渲染器按字体的选中代际重建缓存：被选中集合内的字体在替换后立即对激活的字幕轨生效；仅注册而未选中的字体不会触发渲染器重建。

弹幕弾幕#

弹幕输入为 Bilibili XML（文件或 URL）与 JSON（内联字符串）。两条加载路径：

  • load_danmaku_file / load_danmaku_json — 替换全部弹幕为一条匿名轨。
  • add_danmaku_track_file / add_danmaku_track_json — 建立命名多轨列表，每轨可单独启停与偏移。

轨级 offset_micros 偏移单条轨的时间线，全局偏移作用于所有轨。布局在 erika-danmaku 线程中生成，plan 以 generation 与 media time 门控，与视频保持同步。

DFM+ 布局

弹幕布局由 DFM+ 碰撞避让引擎完成：滚动、顶部与底部三种模式各自的轨道分配、密度限制与覆盖策略。绘制走 glyph atlas，字形一次性栅格化进 atlas，之后逐帧以实例化顶点绘制。

布局参数经 ErikaDanmakuConfig 控制：

字段含义
font_size弹幕逻辑字号，与 NipaPlay 默认弹幕字体一致，按表面 scale 换算为 glyph 像素。
opacity / outline_width / shadow_*透明度、描边宽度、阴影偏移与样式。
display_area弹幕可占的显示区域比例。
scroll_duration_seconds / scroll_speed_factor滚动时长与速度系数。
merge_duplicates重复弹幕合并。
allow_stacking / allow_scroll_overwrite同轨堆叠与滚动覆盖策略。
max_quantity / max_lines_per_mode弹幕总量与单模式最大行数。
block_top / block_bottom / block_scroll按模式屏蔽弹幕。

屏蔽词经 set_danmaku_block_words_json 提供，JSON 数组格式，逐条匹配弹幕文本。

弹幕 JSON 契约规范

load_danmaku_json 与 add_danmaku_track_json 接受内联 JSON。输入根节点支持两类结构：

  • Item 数组： [ { ... }, { ... } ]
  • 包装对象： 包含 comments、danmaku 或 items 数组的对象，例如 { "comments": [ ... ] }。同时也兼容按行分割的 JSON Lines (JSONL)。

每个弹幕 item 的支持字段如下（括号内为兼容别名）：

字段名类型默认值说明
content
(text, c)		String—弹幕正文。缺失或仅含空白字符的条目会被自动跳过。
time
(t)		Number / String0.0弹幕呈现时间（秒），支持浮点秒数（如 12.45）。
type
(mode, y)		String / Number"scroll"弹幕类型：scroll / 1（滚动）、bottom / 4（底部固定）、top / 5（顶部固定）、reverse / 6（逆向滚动）、special / 7（高级特殊，当前解析后不进入布局渲染）。亦可使用数值字段 type_code / mode_code。
color
(r)		Number / String白色弹幕颜色：支持十进制 RGB 整数（如 16777215）、完整的 #RRGGBB 十六进制字符串（如 "#FFFFFF"）或 CSS rgb(r,g,b)。注：不应使用 #FFF 等 3 位缩写（会按 16 进制直接解析为 0x000FFF）。
font_size
(fontSize, size, s)		Number / String25.0源参考字号（点）。最终呈现字号还会相对全局配置与表面 scale 缩放。
opacity
(alpha, a)		Number / String1.0自定义不透明度（0.0 ~ 1.0）。
is_me
(isMe, self, mine)		Boolean / Numberfalse是否为当前用户自发弹幕（具备布局排版优先权，避免被防堆叠策略过滤）。
idu64 / String顺序分配业务 ID。支持 u64 范围内的无符号整数或十进制字符串；0 视为未提供。

解析与行为约定：

  • id 可省略： 省略、为 0、非法或越界时，Erika 会按其在整份输入中的自然位置顺序分配序号。
  • 精确 u64 解析： 支持 0 到 18446744073709551615（u64::MAX）范围内的无符号整数或十进制字符串，解析时不经过浮点转换，杜绝 JS/JSON 双精度浮点精度截断。
  • 业务 ID 与布局身份解耦： 业务 ID 允许重复或在多轨合并时产生跨源冲突。调用方不应拼接 track ID，也不需要为了排版唯一性而合成特殊 ID。
  • 跨滑窗连贯性保证： 弹幕会话在多轨合并后为当前内容版本独立分配内部布局身份。在连续同一会话中，连续时间滑窗会严格继承历史准入和轨道分配决定，对外承诺“弹幕不会在滑窗刷新后半途出现或换轨”（viewport 尺寸变化、时间线内容变更或布局配置调整时除外）。
  • 容错机制： 根节点格式错误直接返回失败；单条 item 若缺少正文或正文为空白会被跳过，不中断整批解析；非法可选字段回退为默认值；未知业务字段（如 cid、danmakuId）安全忽略。

标准弹幕 JSON 样例

[
  { "time": 1.5, "content": "前方高能预警", "type": "scroll", "color": "#FF0000" },
  { "t": 2.0, "c": "名场面打卡", "mode": 5, "color": 16777215, "id": "9007199254740993" },
  { "time": 4.8, "content": "弹幕合影", "is_me": true, "opacity": 0.9 }
]
