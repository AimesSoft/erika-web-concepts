Rust embedded

Rust Embedding

Rust is used directly by the host erika crate of Player or PresenterRuntime. The host senses status changes through event channels and subscribes to decoded video frames, audio samples, and subtitles on demand.

  • entrance Player / PresenterRuntime
  • event 12 kinds
  • frame subscription 3 channels

Dependencies and buildsセットアップ#

Cargo.toml

[dependencies]
erika = { git = "https://github.com/AimesSoft/liberika", tag = "v0.3.0" }

Before the first source code construction of Apple, Windows, Android and OpenHarmony, the preset LGPL native dependencies (FFmpeg, libass, dav1d, etc.) need to be compiled through xtask:

shell

cargo run -p xtask -- deps build --all --profile lgpl
cargo build -p erika

Play life cycleライフサイクル#

src/main.rs

use std::time::Duration;
use erika::{MediaRequest, Player, PlayerConfig, PlayerState};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let player = Player::new(PlayerConfig::default());

    /* 1. 同步打开媒体：完成探测与轨道解析，返回时状态已为 Ready */
    player.open(MediaRequest::new("/path/to/video.mp4"))?;

    /* 2. 启动后台解码与时钟驱动 */
    player.play()?;

    /* 3. 播放控制：seek 向工作线程投递命令并立即返回 */
    player.pause()?;
    player.seek(Duration::from_millis(1500))?;
    player.set_playback_rate(1.25)?;
    player.stop()?;

    /* 4. 关闭播放器：安全终止后台工作线程 */
    player.close()?;
    Ok(())
}

Key points of method semantics:

  • open The detection is completed synchronously: Player::open() Media decapsulation, stream information detection and track extraction will be executed simultaneously, and return Ok(()) Published before DurationChanged、TracksChanged Wait for the initial event and set the state to Ready。
  • play Start an asynchronous playback loop: play() Wake up the background worker thread to start decoding and synchronize the audio and video clock, and the playback state moves to Playing。
  • seek Is non-blocking delivery: seek() Return immediately after delivering the jump target time to the command queue, and the background thread completes keyframe positioning in the pause or playback state.
  • close Guaranteed safe recycling: close() Wait for the background decoding thread to exit safely before returning, and then it can be safely discarded. Player Example.

MediaRequest Supports HTTP(S) URL and custom request headers:

Online media request with Headers

let request = MediaRequest::new("https://example.com/stream.m3u8")
    .with_http_headers(vec![
        ("User-Agent".into(), "CustomPlayer/1.0".into()),
        ("Referer".into(), "https://example.com".into()),
    ]);
player.open(request)?;

event subscriptionイベント#

in open() Called before player.subscribe(), you can receive the initial event and subsequent state changes when opening:

event consumption loop

use erika::{PlayerEvent, PlayerState};

let events = player.subscribe();

while let Ok(event) = events.recv() {
    match event {
        PlayerEvent::StateChanged(PlayerState::Closed) => {
            println!("播放器已完全关闭");
            break;
        }
        PlayerEvent::StateChanged(state) => {
            println!("状态迁移: {:?}", state);
        }
        PlayerEvent::DurationChanged(duration) => {
            println!("总时长: {:?}", duration);
        }
        PlayerEvent::PositionChanged(pos) => {
            println!("当前进度: {:?}", pos);
        }
        PlayerEvent::BufferingChanged(is_buffering) => {
            println!("缓冲状态: {}", is_buffering);
        }
        PlayerEvent::TracksChanged(tracks) => {
            println!("可用轨道数: {}", tracks.len());
        }
        PlayerEvent::Error(err) => {
            eprintln!("播放器错误: {:?}", err);
        }
        _ => {}
    }
}

Frame subscription with Presenter hostingフレーム purchase verification#

The Rust host of the self-built rendering pipeline can directly subscribe to the decoded data frame:

Subscribe to audio, video and subtitle frames

let video_rx = player.subscribe_video_frames();
let audio_rx = player.subscribe_audio_frames();
let subtitle_rx = player.subscribe_subtitle_frames();

/* 在宿主渲染循环中非阻塞拉取 */
if let Ok(video_frame) = video_rx.try_recv() {
    /* video_frame: 像素格式、尺寸、PTS、纹理句柄或 CPU 内存块 */
}
if let Ok(audio_frame) = audio_rx.try_recv() {
    /* audio_frame: PCM 采样数据与声道参数 */
}

The frame subscription channel has a back-pressure control mechanism. When the queue is full, new frames currently to be sent will be discarded to ensure smooth playback. The kernel needs to host the entire set of GPU rendering (Metal / D3D11 / wgpu) and audio clock hosts. It is recommended to use it directly. PresenterRuntime：

PresenterRuntime Hosted Presentation

use erika::presenter::{PresenterConfig, PresenterRuntime};

let mut presenter = PresenterRuntime::new(PresenterConfig::default())?;
presenter.open(MediaRequest::new("/path/to/video.mp4"))?;
presenter.play()?;

/* 在显示时钟驱动回调中调用 */
let stats = presenter.render_tick(host_time_seconds)?;

HTTP cache#

httpReadAheadBytes Determines the number of bytes to read forward, the default is 2 MiB;httpBackBufferBytes Determine how much played data to keep, the default is 16 MiB. Omit both or pass 0 to use the default value. The readahead default value can also be given by ERIKA_HTTP_READAHEAD_BYTES set up.

The fallback seek in the rollback cache can directly reuse the downloaded data. High bitrate videos require a larger budget: a video of 80 Mbit/s would require about 100 MB to retain for about 10 seconds. The cache is limited by bytes and does not represent a fixed number of playback seconds.

Rust

let request = MediaRequest::new("https://example.com/video.mp4")
    .with_http_read_ahead_bytes(8 * 1024 * 1024)
    .with_http_back_buffer_bytes(128 * 1024 * 1024);
player.open(request)?;
