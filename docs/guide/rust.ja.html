Rust Embedding

Rust はホストによって直接使用されます erika crateの Player または PresenterRuntime。ホストはイベント チャネルを通じてステータスの変化を感知し、デコードされたビデオ フレーム、オーディオ サンプル、および字幕をオンデマンドでサブスクライブします。

  • 入口 Player / PresenterRuntime
  • PlayerEvent 12 種類
  • フレームのサブスクリプション 3チャンネル

依存関係とビルドセットアップ#

Cargo.toml

[dependencies]
erika = { git = "https://github.com/AimesSoft/liberika", tag = "v0.3.1" }

Apple、Windows、Android、および OpenHarmony の最初のソース コードを構築する前に、プリセット LGPL ネイティブ依存関係 (FFmpeg、libass、dav1d など) を xtask を通じてコンパイルする必要があります。

shell

cargo run -p xtask -- deps build --all --profile lgpl
cargo build -p erika

遊びのライフサイクルライフサイクル#

src/main.rs

use std::time::Duration;
use erika::{MediaRequest, Player, PlayerConfig, PlayerState};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let player = Player::new(PlayerConfig::default());

    /* 1. 同步打开媒体：完成探测与轨道解析，返回时状态已为 Ready */
    player.open(MediaRequest::new("/path/to/video.mp4"))?;

    /* 2. 启动后台解码与时钟驱动 */
    player.play()?;

    /* 3. 播放控制：seek 向工作线程投递命令并立即返回 */
    player.pause()?;
    player.seek(Duration::from_millis(1500))?;
    player.set_playback_rate(1.25)?;
    player.stop()?;

    /* 4. 关闭播放器：安全终止后台工作线程 */
    player.close()?;
    Ok(())
}

メソッドのセマンティクスの重要なポイント:

  • open 検出は同期的に完了します。 Player::open() メディアのカプセル化解除、ストリーム情報の検出、トラックの抽出を同時に実行し、リターンします。 Ok(()) 以前に公開されました DurationChanged、TracksChanged 最初のイベントを待ち、状態を次のように設定します。 Ready。
  • play 非同期再生ループを開始します。 play() バックグラウンド ワーカー スレッドを起動してデコードを開始し、オーディオとビデオのクロックを同期すると、再生状態は次のようになります。 Playing。
  • seek ノンブロッキング配信です: seek() ジャンプ目標時間をコマンドキューに渡したらすぐに戻り、バックグラウンドスレッドは一時停止または再生状態でキーフレームの配置を完了します。
  • close 安全なリサイクルの保証: close() バックグラウンドのデコード スレッドが安全に終了するまで待ってから戻ると、安全に破棄できます。 Player 例。

MediaRequest HTTP(S) URL およびカスタム リクエスト ヘッダーをサポートします。

Headers によるオンライン メディア リクエスト

let request = MediaRequest::new("https://example.com/stream.m3u8")
    .with_http_headers(vec![
        ("User-Agent".into(), "CustomPlayer/1.0".into()),
        ("Referer".into(), "https://example.com".into()),
    ]);
player.open(request)?;

イベントのサブスクリプションイベント#

で open() 前に呼び出された player.subscribe()を開くと、最初のイベントとその後の状態変化を受け取ることができます。

イベント消費ループ

use erika::{PlayerEvent, PlayerState};

let events = player.subscribe();

while let Ok(event) = events.recv() {
    match event {
        PlayerEvent::StateChanged(PlayerState::Closed) => {
            println!("播放器已完全关闭");
            break;
        }
        PlayerEvent::StateChanged(state) => {
            println!("状态迁移: {:?}", state);
        }
        PlayerEvent::DurationChanged(duration) => {
            println!("总时长: {:?}", duration);
        }
        PlayerEvent::PositionChanged(pos) => {
            println!("当前进度: {:?}", pos);
        }
        PlayerEvent::BufferingChanged(is_buffering) => {
            println!("缓冲状态: {}", is_buffering);
        }
        PlayerEvent::TracksChanged(tracks) => {
            println!("可用轨道数: {}", tracks.len());
        }
        PlayerEvent::Error(err) => {
            eprintln!("播放器错误: {:?}", err);
        }
        _ => {}
    }
}

Presenter ホスティングによるフレーム サブスクリプションフレーム購入確認#

自己構築されたレンダリング パイプラインの Rust ホストは、デコードされたデータ フレームを直接サブスクライブできます。

オーディオ、ビデオ、字幕フレームを購読する

let video_rx = player.subscribe_video_frames();
let audio_rx = player.subscribe_audio_frames();
let subtitle_rx = player.subscribe_subtitle_frames();

/* 在宿主渲染循环中非阻塞拉取 */
if let Ok(video_frame) = video_rx.try_recv() {
    /* video_frame: 像素格式、尺寸、PTS、纹理句柄或 CPU 内存块 */
}
if let Ok(audio_frame) = audio_rx.try_recv() {
    /* audio_frame: PCM 采样数据与声道参数 */
}

フレーム サブスクリプション チャネルにはバック プレッシャー制御メカニズムがあります。キューがいっぱいになると、スムーズな再生を確保するために、現在送信される新しいフレームは破棄されます。カーネルは、GPU レンダリング (Metal / D3D11 / wgpu) およびオーディオ クロック ホストのセット全体をホストする必要があります。直接使用することをお勧めします。 PresenterRuntime：

PresenterRuntime がホストするプレゼンテーション

use erika::presenter::{PresenterConfig, PresenterRuntime};

let mut presenter = PresenterRuntime::new(PresenterConfig::default())?;
presenter.open(MediaRequest::new("/path/to/video.mp4"))?;
presenter.play()?;

/* 在显示时钟驱动回调中调用 */
let stats = presenter.render_tick(host_time_seconds)?;

HTTP キャッシュ#

httpReadAheadBytes 前方に読み取るバイト数を決定します。デフォルトは 2 MiB です。httpBackBufferBytes 保持する再生データの量を決定します。デフォルトは 16 MiB です。両方を省略するか、0 を渡してデフォルト値を使用します。先読みのデフォルト値は次のように指定することもできます。 ERIKA_HTTP_READAHEAD_BYTES 設定。

ロールバック キャッシュ内のフォールバック seek は、ダウンロードされたデータを直接再利用できます。高ビットレートのビデオには、より大きな予算が必要です。80 Mbit/s のビデオを約 10 秒保持するには、約 100 MB が必要になります。キャッシュはバイト数によって制限されており、固定の再生秒数を表しません。

Rust

let request = MediaRequest::new("https://example.com/video.mp4")
    .with_http_read_ahead_bytes(8 * 1024 * 1024)
    .with_http_back_buffer_bytes(128 * 1024 * 1024);
player.open(request)?;

0.3.1 では MediaRequest::with_start_position、自然終了時の PlayerEvent::Ended、PresenterRuntime::set_subtitle_delay、弾幕付きキャプチャとネイティブフレームテクスチャの出力を追加しました。明示的な停止では Ended は発生しません。
