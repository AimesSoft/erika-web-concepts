Web / WASM access

Browser Playback

Give the original MKV to the browser and retain the ASS special effects, font attachments and danmaku. liberika 0.3.0 uses FFmpeg WASM to decapsulate, WebCodecs to decode, libass to draw subtitles, and then WebGL2 to synthesize a piece of Canvas into the host.

  • version 0.3.0
  • Distribute GitHub Release ZIP
  • environment HTTPS / localhost
  • output SDR

Download and preview#

Download liberika-web-0.3.0.zip, press the same Release SHA256SUMS Verification, complete decompression and access through HTTPS or local HTTP service index.html. The demo page can choose local videos, subtitles and danmaku without the need for a media server.

Run in the unzipped directory

python3 -m http.server 18765 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:18765

The package contains JavaScript, two WASM, Worker, license, build list and demo page. The runtime has not yet been released to npm. Keep the complete directory and relative path when deploying, and correctly provide the JavaScript module and application/wasm MIME; no SharedArrayBuffer or cross-source isolation required.

minimal access#

Put runtime resources into the website liberika/ Table of contents. The example lets the user select a local File, which the Worker reads in chunks. You can also pass a Blob or a cross-origin media URL permitted by the server to open.

HTML + JavaScript module

<input id="media" type="file">
<button id="play" disabled>播放</button>
<canvas id="video" style="width:100%;height:60vh"></canvas>
<pre id="status"></pre>
<script type="module">
import { Player } from './liberika/index.js';
const media = document.querySelector('#media');
const play = document.querySelector('#play');
const status = document.querySelector('#status');
const showError = error => { status.textContent = error.message; };
const player = await Player.create({ canvas: document.querySelector('#video') });
player.addEventListener('error', event => showError(event.detail));
media.onchange = async () => {
  const file = media.files[0];
  if (!file) return;
  media.disabled = true;
  play.disabled = true;
  try {
    const info = await player.open(file);
    status.textContent = `${file.name}：${info.duration.toFixed(1)} 秒`;
    play.disabled = false;
  } catch (error) {
    showError(error);
  } finally {
    media.disabled = false;
  }
};
play.onclick = () => player.play().catch(showError);
// 应用卸载时：await player.destroy();
</script>

Called from user click play(), meets the browser audio policy. When the application unmounts, call await player.destroy(). Canvas can only be transferred once; rebuilding the player after destruction requires a new Canvas, and the original instance should be retained when switching layouts.

If Canvas or the player wants to delay creation, it can be created when the page is initialized. AudioSession, then passed to Player.create({ canvas, audioSession }), ensuring that the audio is prepared for first real user input.

Subtitles, danmaku and playback control#

MKV embedded ASS/SSA and font attachments are automatically handed over to libass; the danmaku reuses the native Rust DFM engine. The subtitles share the Web Audio playback clock with the danmaku and are synthesized in the same Canvas.

Called after opening media

await player.addSubtitle(await subtitleFile.text()); // ASS / SSA / SRT / WebVTT
await player.addDanmaku(await danmakuFile.text());   // Bilibili XML / Dandanplay JSON
await player.configureDanmaku({ opacity: 0.8, fontSize: 30, delay: 0 });
await player.configureSubtitles({ scale: 1 });

Subtitle and danmaku supersampling is enabled by default without changing display size or video resolution. Pass { supersampling: false } separately to disable either; omitted fields retain their current values.

For complete types see index.d.ts。loaded、stats、timeupdate、error、log is CustomEvent, the data is in detail; play / pause / ended is ordinary Event.

Browser and media source requirements#

  • WebCodecs video and audio decoding, OffscreenCanvas, WebGL2 and Web Audio are required. The codec configuration, profile and dimensions are checked when opening; codec support depends on the browser. WASM provides no audio/video software decoder or server-side transcoding fallback.
  • The default request is prefer-hardware, then try no-preference;open(source, { hardwareDecode: false }) Request prefer-software. The preference field does not prove that a hardware decoding was actually used.
  • Large remote files use a bounded HTTP Range cache. For files over 8 MiB, the server must return 206 with the known total length; for cross-origin access, expose Content-Range via Access-Control-Expose-Headers.
  • Containers include MP4/MOV, MKV/WebM, MPEG-TS, AVI, FLV, and Ogg. Whether audio and video codecs can be played depends on the current browser’s WebCodecs query result.
  • The current output is SDR, excluding desktop HDR/EDR/Dolby Vision, ArtCNN, DRM, unknown length live broadcast, bitmap subtitles and embedded non-ASS subtitle conversions. SRT/VTT is converted as plain text and does not preserve the complex VTT layout.
  • On seek, embedded ASS is read ahead from 5 seconds before the target and previously seen events are retained. A first seek into a long event that started earlier may temporarily miss it. Complete external ASS scripts do not have this limitation.

The source code verification record covers the specified versions and materials of Chrome and Safari; Firefox has not yet been verified. For detailed build and test steps, seeSource Code Web Guide。

Build from source#

Use Emscripten 4.0.23, wasm-bindgen-cli 0.2.126, and Rust, Python 3, Node, CMake, Meson, Ninja, make, and pkg-config. For fixed tool versions and initialization steps, see the source code guide above.

shell

cargo run -p xtask -- web build
python3 scripts/serve_web.py
# 已构建原生 C 依赖时可追加 --skip-native

The complete deployable directory is target/web, the intermediate file is target/web-build. The server should put the runtime into the version directory to avoid mixing old and new JS/WASM.
