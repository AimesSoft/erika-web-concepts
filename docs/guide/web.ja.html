Web / WASM アクセス

Browser Playback

オリジナルの MKV をブラウザに提供し、ASS の特殊効果、フォントの添付ファイル、弾幕を保持します。 liberika 0.3.0 は、FFmpeg WASM を使用してカプセル化を解除し、WebCodecs をデコードし、libass を使用して字幕を描画し、その後、WebGL2 を使用して Canvas の一部をホストに合成します。

  • バージョン 0.3.0
  • 配布する GitHub Release ZIP
  • 環境 HTTPS / localhost
  • 出力 SDR

ダウンロードしてプレビューする#

ダウンロード liberika-web-0.3.0.zip、同じReleaseを押します SHA256SUMS 検証、完全な解凍、HTTPS またはローカル HTTP サービス経由のアクセス index.html。デモ ページでは、メディア サーバーを必要とせずに、ローカル ビデオ、字幕、および弾幕を選択できます。

解凍したディレクトリで実行

python3 -m http.server 18765 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:18765

パッケージには、JavaScript、2 つの WASM、Worker、ライセンス、ビルド リスト、デモ ページが含まれています。ランタイムはまだ npm にリリースされていません。デプロイ時に完全なディレクトリと相対パスを保持し、JavaScript モジュールと application/wasm MIME; SharedArrayBuffer やクロスソース絶縁は必要ありません。

最小限のアクセス#

ランタイム リソースを Web サイトに配置する liberika/ 目次。この例ではユーザーがローカル File を選択し、Worker がそれを分割して読み取ります。open には Blob や、サーバーがクロスオリジンアクセスを許可するメディア URL も渡せます。

HTML + JavaScript module

<input id="media" type="file">
<button id="play" disabled>播放</button>
<canvas id="video" style="width:100%;height:60vh"></canvas>
<pre id="status"></pre>
<script type="module">
import { Player } from './liberika/index.js';
const media = document.querySelector('#media');
const play = document.querySelector('#play');
const status = document.querySelector('#status');
const showError = error => { status.textContent = error.message; };
const player = await Player.create({ canvas: document.querySelector('#video') });
player.addEventListener('error', event => showError(event.detail));
media.onchange = async () => {
  const file = media.files[0];
  if (!file) return;
  media.disabled = true;
  play.disabled = true;
  try {
    const info = await player.open(file);
    status.textContent = `${file.name}：${info.duration.toFixed(1)} 秒`;
    play.disabled = false;
  } catch (error) {
    showError(error);
  } finally {
    media.disabled = false;
  }
};
play.onclick = () => player.play().catch(showError);
// 应用卸载时：await player.destroy();
</script>

ユーザーのクリックから呼び出されます play()、ブラウザのオーディオ ポリシーを満たしています。アプリケーションのアンマウント時に await player.destroy() を実行します。 Canvas は 1 回だけ転送できます。破壊後にプレーヤーを再構築するには新しい Canvas が必要で、レイアウトを切り替えるときに元のインスタンスを保持する必要があります。

Canvas またはプレーヤーが作成を遅らせたい場合は、ページの初期化時に作成できます。 AudioSession、次に渡されます Player.create({ canvas, audioSession })、最初の実際のユーザー入力に向けて音声が準備されていることを確認します。

字幕、弾幕、再生制御#

MKV に埋め込まれた ASS/SSA とフォントの添付ファイルは自動的に libass に渡されます。弾幕はネイティブの Rust DFM エンジンを再利用します。字幕は Web Audio 再生クロックを弾幕と共有し、同じ Canvas で合成されます。

メディアを開いた後に呼び出される

await player.addSubtitle(await subtitleFile.text()); // ASS / SSA / SRT / WebVTT
await player.addDanmaku(await danmakuFile.text());   // Bilibili XML / Dandanplay JSON
await player.configureDanmaku({ opacity: 0.8, fontSize: 30, delay: 0 });
await player.configureSubtitles({ scale: 1 });

字幕と弾幕のスーパーサンプリングは既定で有効で、表示サイズや動画解像度は変わりません。それぞれに { supersampling: false } を渡して無効にできます。フィールドを省略すると現在の値を保持します。

操作API と動作
プレイ/ジャンプplay()、pause()、seek(seconds);ジャンプして一時停止または再生状態を保持します。
音量/速度setVolume(0…1)、setRate(0.25…4); 現在の速度によってピッチが変わります。
トラックinfo.tracks、selectAudio(id)、selectSubtitle(id);null は、対応するトラックを閉じます。
章info.chapters start / end (秒単位)、end は null になる可能性があります。電話する seek(chapter.start) ポジショニング。
スクリーンショットcapture(width?) ビデオ、字幕、弾幕を含む PNG Blob を返します。
閉じる/解放するclose() 現在のメディアをクリアした後、open を再実行できます。destroy() Worker、デコーダー、フレーム、GPU、およびオーディオ リソースを解放します。

完全なタイプについては、を参照してください。 index.d.ts。loaded、stats、timeupdate、error、log は CustomEvent、データは detail にあります。 play / pause / ended は通常の Event です。

ブラウザとメディアソースの要件#

  • WebCodecs の動画・音声デコード、OffscreenCanvas、WebGL2、Web Audio が必要です。open 時にコーデック設定、profile、サイズの対応を確認します。対応状況はブラウザーに依存し、WASM には音動画のソフトウェアデコードやサーバー側トランスコードへのフォールバックはありません。
  • 既定では prefer-hardware を要求し、次に no-preference を試みます。open(source, { hardwareDecode: false }) は prefer-software を要求します。設定値は実際にハードウェアデコードが使われたことを証明しません。
  • 大きなリモートファイルは上限付き HTTP Range キャッシュで読み取ります。8 MiB を超える場合、サーバーは 206 と既知の総長を正しく返す必要があります。クロスオリジンでは Access-Control-Expose-Headers で Content-Range を公開します。
  • コンテナーには、MP4/MOV、MKV/WebM、MPEG-TS、AVI、FLV、および Ogg が含まれます。オーディオとビデオのエンコードが再生できるかどうかは、現在のブラウザーの WebCodecs クエリ結果によって決まります。
  • 現在の出力は SDR で、デスクトップ HDR/EDR/Dolby Vision、ArtCNN、DRM、長さ不明のライブ ブロードキャスト、ビットマップ字幕、および埋め込まれた非 ASS 字幕変換を除きます。 SRT/VTT はプレーン テキストとして変換され、複雑な VTT レイアウトは保持されません。
  • 内蔵 ASS はシーク先の 5 秒前から先読みし、既に見たイベントを保持します。より前に始まる長いイベントへ初めてシークした場合、一時的に表示されないことがあります。完全な外部 ASS スクリプトにはこの制限はありません。

ソース コード検証レコードは、Chrome および Safari の指定されたバージョンとマテリアルをカバーします。 Firefox はまだ検証されていません。ビルドとテストの詳細な手順については、次を参照してください。ソースコード Web ガイド。

ソースからビルドする#

Emscripten 4.0.23、wasm-bindgen-cli 0.2.126、および Rust、Python 3、Node、CMake、Meson、Ninja、make、および pkg-config を使用します。修正されたツールのバージョンと初期化手順については、上記のソース コード ガイドを参照してください。

shell

cargo run -p xtask -- web build
python3 scripts/serve_web.py
# 已构建原生 C 依赖时可追加 --skip-native

完全なデプロイ可能なディレクトリは次のとおりです。 target/web、中間ファイルは target/web-build。サーバーは、新旧の JS/WASM の混在を避けるために、ランタイムをバージョン ディレクトリに配置する必要があります。
