Rust 嵌入

Rust Embedding

Rust 宿主直接使用 erika crate 的 Player 或 PresenterRuntime。宿主通过事件通道感知状态变化，按需订阅解码后的视频帧、音频采样与字幕。

  • 入口 Player / PresenterRuntime
  • 事件 12 种
  • 帧订阅 3 通道

依赖与构建セットアップ#

Cargo.toml

[dependencies]
erika = { git = "https://github.com/AimesSoft/Erika", tag = "v0.1.7" }

首次从源码构建前，需通过 xtask 编译预设的 LGPL 原生依赖（FFmpeg、libass、dav1d 等）：

shell

cargo run -p xtask -- deps build --all --profile lgpl
cargo build -p erika

播放生命周期ライフサイクル#

src/main.rs

use std::time::Duration;
use erika::{MediaRequest, Player, PlayerConfig, PlayerState};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let player = Player::new(PlayerConfig::default());

    /* 1. 同步打开媒体：完成探测与轨道解析，返回时状态已为 Ready */
    player.open(MediaRequest::new("/path/to/video.mp4"))?;

    /* 2. 启动后台解码与时钟驱动 */
    player.play()?;

    /* 3. 播放控制 */
    player.pause()?;
    player.seek(Duration::from_millis(1500))?;
    player.set_playback_rate(1.25)?;
    player.stop()?;

    /* 4. 关闭播放器：安全终止后台工作线程 */
    player.close()?;
    Ok(())
}

方法语义要点：

  • open 是同步完成探测的。 Player::open() 会同步执行媒体解封装、流信息探测与轨道提取，并在返回 Ok(()) 前发布 DurationChanged、TracksChanged 等初始事件并将状态置为 Ready。
  • play 启动异步播放循环。 play() 唤醒后台工作线程开始解码与音视频时钟同步，播放状态迁移至 Playing。
  • seek 传入 std::time::Duration。 暂停期间 seek 会同步解码并更新目标位置附近的关键帧画面，播放时钟保持暂停。
  • close 保证安全回收。 close() 等待后台解码线程安全退出后返回，之后可安全丢弃 Player 实例。

MediaRequest 支持 HTTP(S) URL 与自定义请求头：

网络媒体请求与 Headers

let request = MediaRequest::new("https://example.com/stream.m3u8")
    .with_http_headers(vec![
        ("User-Agent".into(), "CustomPlayer/1.0".into()),
        ("Referer".into(), "https://example.com".into()),
    ]);
player.open(request)?;

事件订阅イベント#

通过 player.subscribe() 获取无界事件接收通道：

事件消费循环

use erika::{PlayerEvent, PlayerState};

let events = player.subscribe();

while let Ok(event) = events.recv() {
    match event {
        PlayerEvent::StateChanged(PlayerState::Closed) => {
            println!("播放器已完全关闭");
            break;
        }
        PlayerEvent::StateChanged(state) => {
            println!("状态迁移: {:?}", state);
        }
        PlayerEvent::DurationChanged(duration) => {
            println!("总时长: {:?}", duration);
        }
        PlayerEvent::PositionChanged(pos) => {
            println!("当前进度: {:?}", pos);
        }
        PlayerEvent::BufferingChanged(is_buffering) => {
            println!("缓冲状态: {}", is_buffering);
        }
        PlayerEvent::TracksChanged(tracks) => {
            println!("可用轨道数: {}", tracks.len());
        }
        PlayerEvent::Error(err) => {
            eprintln!("播放器错误: {:?}", err);
        }
        _ => {}
    }
}

原始帧数据拉取フレーム購読#

自建渲染管线的 Rust 宿主可直接订阅解码后的数据帧：

订阅音视频与字幕帧

let video_rx = player.subscribe_video_frames();
let audio_rx = player.subscribe_audio_frames();
let subtitle_rx = player.subscribe_subtitle_frames();

/* 在宿主渲染循环中非阻塞拉取 */
if let Ok(video_frame) = video_rx.try_recv() {
    /* video_frame: 像素格式、尺寸、PTS、纹理句柄或 CPU 内存块 */
}
if let Ok(audio_frame) = audio_rx.try_recv() {
    /* audio_frame: PCM 采样数据与声道参数 */
}

帧订阅通道具备背压控制机制，队列满时会按照丢帧策略丢弃旧帧以保证播放流畅度。需要整套原生呈现与音频时钟的宿主，推荐直接使用 PresenterRuntime。
