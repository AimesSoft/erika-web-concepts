Building and dependencies

Building and Dependencies

liberika's Rust code builds directly with cargo. Native dependencies such as FFmpeg, dav1d, libass, and HarfBuzz are fetched as source, built inside third_party/, and managed by xtask deps. The build scripts keep CI output consistent with local builds.

  • Rust 1.92+
  • Edition 2024
  • Native dependencies 7

Native dependenciesネイティブ依存#

Dependencies for release targets are fetched from upstream source at pinned versions, and the build scripts apply the patches in third_party/patches/.

ComponentVersionDescription
FFmpeg8.1.2Wrapped in crates/erika_ffmpeg_sys. Android uses the patchset erika-android-mediacodec-v4.
dav1d1.5.1AV1 decoding.
libass0.17.5Subtitle rendering.
HarfBuzz14.2.1Text shaping.
FreeType2.14.3Font rasterization.
FriBidi1.0.16Bidirectional text.
zlib1.3.2FFmpeg dependency.

Fetch and build results stay in the workspace's third_party/ directory; nothing is installed into system directories:

third_party/cache     # Downloaded source archives
third_party/src       # Extracted source trees
third_party/build     # Build directories, split by target / profile
third_party/dist      # Output prefixes, split by target / profile

xtask deps依存管理#

Full build workflow

cargo run -p xtask -- deps plan                 # Print the dependency plan
cargo run -p xtask -- deps fetch                # Download and extract sources
cargo run -p xtask -- deps build                # Build the host target
OptionValuesDefault
--profilelgpl / gpl-fulllgpl
--targetSee the target table belowhost
--forceForce a rebuild of native dependenciesOff; completed outputs are reused by default
--allAlso builds the subtitle stack: libass + FreeType + HarfBuzz + FriBidi (fetch downloads the sources of all four as well)Builds only the video stack
--jobsParallelismAutomatic

The two profiles differ in FFmpeg's configure flags. lgpl disables GPL components, disables networking, and enables only the demuxers, parsers, and decoders the playback core needs. gpl-full also enables the GPL components. The default, lgpl, meets release requirements.

Build results store a build marker per target and profile, and FFmpeg and dav1d check the version, patches, and build options against it. After you change xtask/src/main.rs or third_party/patches/, run deps build --force to trigger a rebuild.

Workspace buildワークスペース#

cargo build --workspace
cargo test --workspace

The workspace contains three crates: erika (the kernel), erika_capi (the C ABI), and erika_ffmpeg_sys (the FFmpeg bindings), plus xtask and more than 20 examples. Each example is a minimal program that exercises one specific path:

macOS desktop smoke test

cargo run -p macos_native_demo -- --smoke-seconds 3 /path/to/video.mp4

macos_native_demo is a complete end-to-end Presenter demo: open, play, Metal rendering, and system media controls. The other examples are divided up by name. capi_smoke covers the main C ABI call paths, and playback_tick / player_tick cover the scheduling loops of the two entry points, play and pull.

Building against Linux system libraries#

Linux uses the system FFmpeg 8 and PulseAudio, and builds liberika's patched libass separately. The entry point differs from xtask's release targets:

shell

bash scripts/build_linux_libass.sh
cargo build --locked --release -p erika_capi -p linux_native_demo

For distribution dependencies, the Flutter dynamic library path, and X11 / Wayland examples, see Linux integration. The codecs and license of the system FFmpeg depend on how your distribution built it; setting the lgpl profile does not change system libraries.
