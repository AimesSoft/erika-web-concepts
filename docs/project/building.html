构建与依赖

Building and Dependencies

Erika 的 Rust 代码直接以 cargo 构建；FFmpeg、dav1d、libass、HarfBuzz 等原生依赖以源码方式获取并在 third_party/ 内构建，由 xtask deps 管理。构建脚本保证 CI 与本地产出一致。

  • Rust 1.92+
  • edition 2024
  • 原生依赖 7 个

前置依赖前提#

目标工具
macOS / iOS / tvOSXcode Command Line Tools；nasm、meson、ninja、pkg-config（Homebrew）。
WindowsMSYS2（UCRT64）内的 make、tar、pkgconf、perl、zip；nasm；Python 的 meson、ninja；LLVM（LIBCLANG_PATH 指向 bin/）。
AndroidAndroid SDK 与 NDK（r29，API 26）。
OpenHarmonyDevEco Studio 与对应 SDK / NDK。

原生依赖ネイティブ依存#

全部依赖以固定版本从上游源码获取，构建脚本应用 third_party/patches/ 内的补丁。

组件版本说明
FFmpeg8.1.2封装于 crates/erika_ffmpeg_sys；Android 使用 patchset erika-android-mediacodec-v4。
dav1d1.5.1AV1 解码。
libass0.17.5字幕渲染。
HarfBuzz14.2.1文字整形。
FreeType2.14.3字体光栅化。
FriBidi1.0.16双向文本。
zlib1.3.2FFmpeg 依赖。

fetch 与 build 结果位于工作区内的 third_party/，不安装到系统目录：

third_party/cache     # 下载的源码压缩包
third_party/src       # 解压后的源码树
third_party/build     # 按 target / profile 分隔的构建目录
third_party/dist      # 按 target / profile 分隔的产物前缀

xtask deps依存管理#

完整构建流程

cargo run -p xtask -- deps plan                 # 打印依赖计划
cargo run -p xtask -- deps fetch                # 下载并解压源码
cargo run -p xtask -- deps build                # 构建 host 目标
选项取值默认
--profilelgpl / gpl-fulllgpl
--target见下方 target 表host
--force—跳过已完成的构建
--all额外构建字幕栈：libass + FreeType + HarfBuzz + FriBidi（fetch 时同时抓取这四者源码）只构建视频栈
--jobs并行度自动

两个 profile 的差异在 FFmpeg 的 configure 标志。lgpl 禁用 GPL 组件、禁用 network、只启用播放内核需要的 demuxer / parser / decoder；gpl-full 在此基础上启用 GPL 部分。默认 lgpl 满足发布需要。

构建结果以目标文件时间戳为准。改动了 xtask/src/main.rs 或 third_party/patches/ 之后需要 deps build --force 触发重建。

工作区构建ワークスペース#

cargo build --workspace
cargo test --workspace

工作区包含三个 crate：erika（内核）、erika_capi（C ABI）、erika_ffmpeg_sys（FFmpeg 绑定），以及 xtask 与 20 余个示例。示例是验证特定路径的最小程序：

macOS 桌面端冒烟

cargo run -p macos_native_demo -- --smoke-seconds 3 /path/to/video.mp4

macos_native_demo 是完整的 presenter 端到端演示：打开、播放、Metal 渲染与系统媒体控制。其他示例按名称分工，capi_smoke 覆盖 C ABI 的主要调用路径，playback_tick / player_tick 覆盖 play / pull 两条入口的调度循环。
