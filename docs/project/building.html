构建与依赖

Building and Dependencies

liberika 的 Rust 代码直接以 cargo 构建；FFmpeg、dav1d、libass、HarfBuzz 等原生依赖以源码方式获取并在 third_party/ 内构建，由 xtask deps 管理。构建脚本保证 CI 与本地产出一致。

  • Rust 1.92+
  • edition 2024
  • 原生依赖 7 个

前置依赖前提#

目标工具
macOS / iOS / tvOSXcode Command Line Tools；nasm、meson、ninja、pkg-config（Homebrew）。
WindowsMSYS2（UCRT64）内的 make、tar、pkgconf、perl、zip；nasm；Python 的 meson、ninja；LLVM（LIBCLANG_PATH 指向 bin/）。
AndroidAndroid SDK 与 NDK（r29，API 26）。
OpenHarmonyDevEco Studio 与对应 SDK / NDK。

原生依赖ネイティブ依存#

发布目标的依赖以固定版本从上游源码获取，构建脚本应用 third_party/patches/ 内的补丁。

组件版本说明
FFmpeg8.1.2封装于 crates/erika_ffmpeg_sys；Android 使用 patchset erika-android-mediacodec-v4。
dav1d1.5.1AV1 解码。
libass0.17.5字幕渲染。
HarfBuzz14.2.1文字整形。
FreeType2.14.3字体光栅化。
FriBidi1.0.16双向文本。
zlib1.3.2FFmpeg 依赖。

fetch 与 build 结果位于工作区内的 third_party/，不安装到系统目录：

third_party/cache     # 下载的源码压缩包
third_party/src       # 解压后的源码树
third_party/build     # 按 target / profile 分隔的构建目录
third_party/dist      # 按 target / profile 分隔的产物前缀

xtask deps依存管理#

完整构建流程

cargo run -p xtask -- deps plan                 # 打印依赖计划
cargo run -p xtask -- deps fetch                # 下载并解压源码
cargo run -p xtask -- deps build --all          # 构建 host 目标
选项取值默认
--profilelgpl / gpl-fulllgpl
--ffmpegFFmpeg 格式集合（full、common、slim 或 slim,<group>）full
--crtWindows C 运行库（dynamic / static）dynamic
--target见下方 target 表host
--force强制重建原生依赖关闭；默认复用已完成产物
--all额外构建字幕栈：libass + FreeType + HarfBuzz + FriBidi（fetch 时同时抓取这四者源码）只构建视频栈
--jobs并行度自动

两个 profile 的差异在 FFmpeg 的 configure 标志。lgpl 禁用 GPL 组件、禁用 network、只启用播放内核需要的 demuxer / parser / decoder；gpl-full 在此基础上启用 GPL 部分。默认 lgpl 满足发布需要。

构建结果按目标与 profile 保存构建标记；FFmpeg 和 dav1d 会核对版本、补丁及构建选项。改动了 xtask/src/main.rs 或 third_party/patches/ 之后需要 deps build --force 触发重建。

Windows / MSVC#

0.3.8 起，Windows x64 和 ARM64 上的 host 自动解析为对应的 MSVC 目标，依赖目录与不带 --target 的 cargo build 一致。需要其他架构时仍可显式指定，x64 示例：

PowerShell

cargo run -p xtask -- deps build --all --profile lgpl --target x86_64-pc-windows-msvc
$env:ERIKA_NATIVE_TARGET = "x86_64-pc-windows-msvc"
cargo build --locked -p erika_capi --target x86_64-pc-windows-msvc

ARM64 改用 aarch64-pc-windows-msvc。默认链接动态 CRT（/MD），不要添加 --crt static；只有 Rust 使用 -C target-feature=+crt-static 时才需要该选项，依赖会放入独立的 lgpl-crt-static 目录。

工作区构建ワークスペース#

cargo build --workspace
cargo test --workspace

工作区包含四个库 crate：erika（内核）、erika_capi（C ABI）、erika_plugin（插件 ABI）、erika_ffmpeg_sys（FFmpeg 绑定），以及 xtask 与 20 余个示例。示例是验证特定路径的最小程序：

macOS 桌面端冒烟

cargo run -p macos_native_demo -- --smoke-seconds 3 /path/to/video.mp4

macos_native_demo 是完整的 presenter 端到端演示：打开、播放、Metal 渲染与系统媒体控制。其他示例按名称分工，capi_smoke 覆盖 C ABI 的主要调用路径，playback_tick / player_tick 覆盖 play / pull 两条入口的调度循环。

Linux 发布与源码构建#

0.3.7 起提供 x64 / ARM64 × bundled / system 四种 Linux ZIP，均以 Ubuntu 22.04 / glibc 2.35 为基线。发布构建使用原生同架构 GNU/Linux、Rust 1.92+、Meson 1.8.5 与 CI 所列开发工具；不用系统自带的旧 Rust/Meson。两个模式分别运行：

shell

ERIKA_LINUX_DEPENDENCIES=bundled bash scripts/build_linux_release.sh

ERIKA_LINUX_DEPENDENCIES=system bash scripts/build_linux_release.sh

脚本准备固定的 FFmpeg 8 SDK 和构建头文件，输出隔离在 target/linux-<mode>/<triple>/release，ZIP 在 dist/。bundled 内嵌媒体依赖；system 需要宿主提供匹配的 FFmpeg 8 共享库。两者仍需系统音频与图形驱动。Ubuntu 26.04 的系统库构建仍可用：先运行 scripts/build_linux_libass.sh，再 cargo build --locked --release -p erika_capi -p linux_native_demo。

Rust / C / Flutter · HAL patch · PIC

系统 FFmpeg 的编解码器和许可证取决于发行版构建；设置 lgpl profile 不会改变系统库。
