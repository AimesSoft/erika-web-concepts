Changelog

Changelog

Changes that are visible to the host, listed by version. Entries that were later reverted are omitted; the repository’s root CHANGELOG.md is authoritative for the full history. Breaking changes in 0.1.3 and earlier are summarized at the end of this page.

  • Current 0.3.1
  • Released 2026-10-31

0.3.1 · 2026-10-31#

  • Added opening at a requested position (including the first frame and Ready position), a natural-ended event, subtitle delay and current subtitle text.
  • Added a separate danmaku-inclusive capture and native frame texture export. The original capture still excludes danmaku. Fixed OpenHarmony text subtitle rendering and Android screenshot danmaku selection.

Core and Flutter 0.3.1 are available. As of 2026-10-31, the latest public Swift SDK and OHPM package remain at 0.3.0. Release notes.

0.3.0 · 2026-10-25#

Default behavior changes: Subtitle and danmaku supersampling is now on by default for native and Web, and can be turned off separately. Software video decoding now uses frame/slice multithreading by default, with FFmpeg choosing the thread count. Set ERIKA_VIDEO_DECODE_THREADS=1 to restore single-threaded decoding.

Web, export, and diagnostics

  • Added a standalone Web / WASM backend: FFmpeg demuxing, WebCodecs decoding, libass ASS/SSA subtitles with font attachments, Rust danmaku, a Web Audio clock, and WebGL2 compositing. It supports local files, HTTP Range, multiple tracks, chapters, and PNG screenshots; codec support depends on the browser.
  • The release now includes liberika-web-0.3.0.zip, which ships the full runtime, license, and a demo page together; its checksum is listed in SHA256SUMS.
  • Added standalone RGBA / PNG frame export and continuous frame-capture sessions. They reuse decoder state and tone-map HDR to SDR.
  • Added a redacted log ring, decoding and hardware-fallback diagnostics, and an audio/presentation timing snapshot. listMethods now exposes the JSON interface and the blocking / writesFiles properties.
  • Added a chapters query to the Presenter JSON bridge, without extending existing C structs.

Fixes and compatibility

  • Fixed pause seeking, long subtitles that span a seek, and subtitle updates after switching tracks while paused (#171).
  • iOS / tvOS now keep optional interfaces based on symbol availability, for compatibility with older runtimes and to keep static linking from dropping new symbols (#170).
  • Failed tail reads on plain HTTP are now treated as EOF; Range validation and resource-changed errors are preserved (#169).
  • Danmaku system-font fallback now uses a zero-copy coverage check and a bounded LRU, which fixes memory spikes and preserves visible characters (#173).
  • The erika_play trace now records why startup failed. Improved Windows, Android, and HarmonyOS integration.
  • Renamed the project to liberika. The Rust crate erika, the C ABI erika_*, and the Flutter/OHPM package names remain compatible.

GitHub Release, Flutter 0.3.0, Swift SDK 0.3.0, and OHPM erika 0.3.0 are all public. For the complete record, see the source CHANGELOG.

0.2.1 · 2026-10-02#

  • HTTP connections, TLS, response reads, and background read-ahead can now be canceled. stop, close, and reopen reclaim network threads and caches, which reduces exit stalls and leftover resources.
  • The Flutter, Swift, and OpenHarmony SDKs can adjust the back buffer through httpBackBufferBytes (default 16 MiB).
  • Completed WMV / WMA support, software fallback for dav1d 8-bit / 10-bit AV1, and software frame upload on Windows.
  • iOS now schedules video, subtitles, and danmaku against the display target time and coalesces backlogged render callbacks.
  • Added experimental Linux support: X11 / Wayland, PulseAudio, NVDEC / VA-API, Flutter textures, and a native Wayland video layer.
  • P010 upload now preserves 10-bit precision, which improves HDR color conversion.

0.2.0 · 2026-09-23#

  • HTTP persistent connections, background read-ahead, a seek window, and resume after interruption. Request headers and cache validators are kept with the request.
  • Added Dolby Vision RPU reshaping and color conversion, covering Profile 5 / 8 and Profile 7 base-layer mapping.
  • Tone mapping now defaults to BT.2390 / IPT. Added more operators, target black point and contrast controls, and a cached perceptual gamut LUT.
  • HDR10 software frames now adjust the mapping using scene luminance statistics, and Apple EDR output follows the display headroom.

0.1.8 · 2026-09-07バージョン#

Added HTTP open options and read-ahead window configuration, a unified SDK publishing entry point, and Windows Flutter SDR textures. Presenter configuration gains a video alpha mode, so native hosts must update the header and runtime together.

Transparent video and cross-platform native GPU compositing (#124)

  • Added packed-alpha video presentation (ErikaVideoAlphaMode.packedAlphaRight): for sources with color in the left half and alpha in the right half, the GPU reconstructs premultiplied alpha and presents at half the encoded width. Players that do not request this mode behave as before.
  • macOS gains an IOSurface + Metal Flutter Texture path (ErikaTextureVideoView) that provides Flutter opacity, clipping, transforms, and color filters without a per-frame CPU readback. When you need background-aware blending, switch to native CAMetalLayer (supports overlayBlendMode and layer opacity).
  • Transparent video on Windows now composites through DirectComposition: a premultiplied-alpha composition swap chain binds directly to the Flutter HWND, replacing the separate opaque pop-up window. It supports srcOver / overlay blending and opacity, and overlay can sample the real game background inside the same HWND. Opaque video keeps the existing HWND playback path.
  • Raised the native playback rate limit from 4× to 16×, so short animations and effect clips can play faster.
  • C ABI additions: erika_presenter_create_with_output_mode_and_alpha, erika_presenter_attach_flutter_texture / erika_presenter_set_flutter_texture_buffer, and erika_presenter_windows_composition_swapchain_iunknown (AddRef/Release ownership).

Danmaku continuity and the JSON contract (#121)

  • Track assignment and admission decisions now stay stable across consecutive planning windows, so discarded danmaku no longer reappear midway and visible danmaku no longer switch tracks.
  • Decoupled the host-supplied danmaku business ID from the kernel’s internal layout identity. The optional JSON ID can now be parsed as an exact u64 or a decimal string, which avoids ID truncation from double-precision rounding.
  • Formalized and documented the inline danmaku JSON contract, which accepts a standard array or a root object with comments / danmaku / items.

0.1.7バージョン#

Flutter package release

  • erika_flutter is now published to pub.dev, with the license, changelog, metadata, examples, and standalone tests in the package.
  • Verified native bundles pinned to the package version are now the default build method for Android, Apple, Windows, and OpenHarmony. To build from source, set ERIKA_FORCE_SOURCE_BUILD=1.
  • Android runtime archives are now split by ABI: app builds download only the architecture they need and no longer bundle the native-embedder static library.
  • Each release now includes a SHA256SUMS manifest covering all native archives.
  • The GitHub Actions consumption builds for the six platforms are now independent, and package builds no longer depend on the monorepo.

OpenHarmony native package release

  • Added the OpenHarmony ArkTS / OHPM package erika, targeting arm64 and API 18+.
  • Provides the XComponent surface lifecycle, playback control, renderTick() frame scheduling, events, and a screenshot API, along with a standalone integration guide.

0.1.6バージョン#

Rendering and playback

  • Added ArtCNN C4F16 DS luma upscaling with denoising and sharpening, aimed at degraded anime sources, across the Rust, C, Flutter, Metal, and wgpu interfaces.
  • Presenter rendering on Android and macOS moved off the app UI / main thread. Android AHardwareBuffer conversion bandwidth is lower, and D3D11 no longer reuses frames across devices.
  • Apple platforms now choose SDR / EDR output based on the source content. Resource status is exposed through the Android, Windows, and OpenHarmony integrations.

Integration and behavior

  • Danmaku scroll overwrite is now off by default, so already-stable danmaku are not overwritten during high-density playback.
  • Restored the Windows system media controls build. The ArkTS declarations in the OpenHarmony Flutter plugin are now explicit.

0.1.5バージョン#

System media controls and background audio

  • Now Playing metadata, playback state, timeline, play / pause / seek, and previous/next track navigation, across six platforms: iOS, tvOS, macOS, Android, Windows, and OpenHarmony.
  • Optional background audio playback on iOS and Android. Video decoding is suspended in the background, and lifecycle callbacks are queued behind a bounded barrier so they cannot block the app thread indefinitely.
  • Opening media without ErikaMediaMetadata now clears stale metadata. pause / play timing is now deterministic, and Android media callbacks are isolated per Flutter engine.
  • Android caches cover art, and media notifications are no longer rebuilt when the native playback state has not changed.

Platforms and release artifacts

  • tvOS plugin and native target for devices and arm64 / x86_64 simulators, including Metal presentation, Apple audio, VideoToolbox, subtitles, danmaku, screenshots, and HTTP sources.
  • Added erika-capi-tvos.zip (device + universal simulator xcframework), and added it to the release workflow automatically.
  • Optional prebuilt consumption on OpenHarmony: a CMake build can download a tagged liberika_capi.so and place it next to liberika_flutter.so, and falls back to a source build on failure.
  • CI and release for macOS / iOS / tvOS now use the macOS 26 runner. macOS x64 and arm64 are cross-built and then merged into a universal package. Zero-length HTTP resources are no longer misdetected as truncated.

In-memory subtitle fonts

  • The in-memory subtitle font registry now spans Rust, the C API, Dart, and each native Flutter embedding. The host can inspect font faces, select an ordered fallback set, replace font data, and clear the registry, all without writing to disk.
  • libass keeps the ordered fallback. TTC / OTC data is shared across faces. When a font at the same path is replaced, the renderer cache is invalidated and the active subtitle track uses the new data immediately.
  • The registry and the selected set now track generations separately. After a renderer rebuild, libass codec private data is replayed. OpenHarmony and tvOS now expose the full in-memory font C API surface.

Playback recovery

  • When audio or video input starves, playback now enters an explicit buffering transition. The playback clock freezes during the stall and re-anchors to the media time once data returns, which avoids the clock running ahead and causing prolonged frame drops or a black screen.

0.1.4バージョン#

Compatibility notes

  • Danmaku outline_width is now a level, not a multiplier. 0 is off, 1 thin, 2 normal, 3 thick; values above 3 clamp to thick. Normal and thick reproduce the widths of the old continuous multiplier at 1.0 and 2.0 exactly, so a host that used to send outline_width: 1.0 must now send 2.0 to keep the same outline. Unmigrated outlines get thinner: at the default font size the rasterization radius halves from 2 px to 1 px.
  • Danmaku font size is now interpreted as pixels per em. PxScale in ab_glyph is the height from ascender to descender, and the old code passed the em size straight in, so text rendered smaller than requested. Text now matches the request, which makes danmaku larger after the upgrade. For PingFang SC the ratio is 1.4, so the same configuration is up to 40% larger. Hosts that want the old look should lower the font size.
  • Danmaku scroll duration now scales with the logical viewport width (×0.9 at 640 pt, ×1.3 at 1920 pt and above). The same configuration scrolls more slowly in large windows.
  • Screenshots no longer include danmaku. capture_* composites only video and subtitles, and the debug HUD is also excluded.

Platforms and release artifacts

  • OpenHarmony playback backend and Flutter plugin: AVCodec H.264 / HEVC hardware decoding, OHNativeBuffer / Vulkan zero-copy presentation, WGPU compositing, subtitles, danmaku, audio, diagnostics, and RGBA screenshots. Releases now include erika-capi-openharmony-arm64.zip.
  • Windows ARM64 native dependencies and an erika_capi build; added erika-capi-windows-arm64.zip.
  • Optional macOS arm64 / x86_64 / universal builds and matching archives.
  • On Apple Silicon, Android source builds now use the general-purpose glslc that ships with the NDK. x86_64 artifacts re-enable FFmpeg’s optimized assembly, so source builds require NASM.

Playback, rendering, and window integration

  • The shared playback clock is now published directly, and frame snapshots sample time, state, and generation atomically. Danmaku, subtitles, and rendering share a single time base.
  • Seeking while paused now decodes and presents a preview frame while the media clock stays frozen. Race conditions around seek preroll, EOF, and a pause or resume right after a seek no longer cause clock rollback, an idle worker, or long black frames.
  • Demux demand for audio and video is now separate, so audio backpressure no longer blocks video packet scanning. Switching or adding subtitles does not reset the audio and video demux selection.
  • macOS presentation was rebuilt on CVDisplayLink, with slow-frame coalescing and a display link reset after a screen change. Redundant overlay attachment and GPU resource work during resize and window migration are reduced.
  • The desktop overlay API supports multiple FlutterViews and secondary windows. The player keeps its surface, visibility, generation, and aspect-fit state when it migrates between host windows.
  • Improved the Windows D3D11 overlay lifecycle, non-blocking presentation, and seek recovery. Subtitles are composited inside the video viewport, while danmaku keep the full-window viewport.

Danmaku and subtitles

  • Danmaku collision bounds now align with the rasterized outline. Fixed the shadow / outline / text layer order, stabilized track preference, and confined high-density overlap to overflow tracks.
  • During an asynchronous reflow, the old danmaku plan keeps moving. Draw-only settings reuse the layout and take effect immediately.
  • Incremental glyph atlas uploads and a reusable Metal instance buffer reduce per-frame DFM allocation and candidate-traversal cost.
  • Charset detection and transcoding for external text subtitles, covering GBK, Big5, Shift_JIS, and UTF-16, with UTF-8 passthrough and a fallback guard for low-confidence or binary input.
  • libass now registers liberika’s built-in Droid Sans Fallback on all platforms. Targets without a system font provider default to that family instead of falling through to an unresolvable Arial.
  • Subtitle fallback and selective style overrides: custom font family and file, RGBA colors, metrics, text attributes, borders, alignment, margins, and blur. The entry points are erika_presenter_set_subtitle_font, erika_presenter_set_subtitle_style, and ErikaPlayer.setSubtitleStyle.

Network and media diagnostics

  • Added erika_open_with_headers and erika_presenter_open_with_headers. Request headers apply to probing, range reads, retries, and prefetching, but are not forwarded to subtitle and danmaku sidecars.
  • Host-supplied headers that liberika manages for transport, and invalid HTTP fields, are now rejected. Hardened HTTP range input handling: ignored Range, wrong offsets, transient failures, partial responses, and repeated prefetch with false EOF; retries are bounded.
  • Track bitrate and rational frame rate metadata now flow through Rust, C, and Dart. An optional native debug HUD covers the decoder, renderer, GPU, audio, output and HDR, and danmaku diagnostics.

Audio, color, and codecs

  • Normalized the surround-to-stereo downmix matrix to prevent clipping.
  • All audio backends now apply a per-callback volume ramp. WASAPI device-loss recovery reports observable recovery state and uses bounded backoff.
  • Metal, WGPU, and D3D11 now decode BT.2100 HLG, and the D3D11 overlay correctly encodes PQ on HDR10 output.
  • Upgraded FFmpeg to 8.1.2. Improved Darwin AV1 hardware-decode import. The last frame is now kept while a seek loads, so the picture no longer flashes black.

0.1.3 and earlier以前#

Version 0.1.3 introduced the full Android playback path (MediaCodec, AHardwareBuffer / wgpu, AAudio, PlatformView, subtitles, danmaku, screenshots, SDR / HDR). Two of its breaking changes are still in effect:

  • Surface size semantics. The width / height passed to attach and resize are the exact drawable size in physical pixels and are no longer multiplied by scale. scale now affects only logical UI content such as danmaku.
  • Asynchronous play. play is now queued and no longer waits for the playback worker. The final outcome is reported by the StateChanged and Error events.
