0.3.0 · 2026-10-25#

Default behavior changes:The subtitles and danmaku supersampling of native and Web are enabled by default and can be turned off respectively; software video decoding enables frame/slice multi-threading by default, and the number of threads is selected by FFmpeg. settings ERIKA_VIDEO_DECODE_THREADS=1 Restore single thread.

Web, export and diagnosis

  • Add independent Web / WASM backend: FFmpeg decapsulation, WebCodecs decoding, libass ASS/SSA subtitles and font attachments, Rust danmaku, Web Audio clocks and WebGL2 synthesis. Supports local files, HTTP Range, multitrack, chapters and PNG screenshots, encoding capabilities depend on browser.
  • Release New liberika-web-0.3.0.zip, the complete runtime, license and demo page are distributed together, and the abstract is included SHA256SUMS。
  • Added independent RGBA / PNG frame export and continuous frame capture sessions; reuse decoding status and map HDR to SDR.
  • Added desensitized log loop, decoding and hardware fallback diagnosis, audio/presentation timing snapshot;listMethods You can find the JSON interface and blocking / writesFiles property.
  • Presenter JSON New chapters Query without extending the existing C structure.

Repairs and compatibility

  • Fix pause jump, long subtitles spanning seek, and subtitle update after pause track cutting (#171).
  • iOS / tvOS Preserve optional interfaces by symbol availability, for compatibility with older runtimes and to avoid static linking losing new symbols (#170).
  • Ordinary HTTP tail read failures are handled as EOF, and Range checksum resource change errors are retained (#169).
  • Danmaku system font fallback uses zero-copy coverage checking and bounded LRU, fixes memory spikes and preserves visible characters (#173).
  • erika_play trace records the reason for startup failure; improves Windows, Android and Hongmeng access.
  • Project renamed liberika; Rust crate erika、C ABI erika_*, Flutter/OHPM package names continue to be compatible.

GitHub Release、Flutter 0.3.0、Swift SDK 0.3.0 and OHPM erika 0.3.0 All have been made public. For complete records seeSource code CHANGELOG。

0.2.1 · 2026-10-02#

  • HTTP connection, TLS, response reading and background pre-reading can be canceled; stop / close / reopening will recycle network threads and caches, reducing exit lag and resource residue.
  • Flutter, Swift and OpenHarmony SDK can pass httpBackBufferBytes Adjust rollback cache, default 16 MiB.
  • Completed WMV / WMA, dav1d 8-bit / 10-bit AV1 software rollback, and Windows software frame upload.
  • iOS schedules videos, subtitles and danmaku according to the display target moment, and merges the backlog of rendering callbacks.
  • Added experimental Linux support: X11 / Wayland, PulseAudio, NVDEC / VA-API, Flutter textures and Wayland native video layer.
  • P010 upload preserves 10-bit accuracy and improves HDR color conversion.

0.2.0 · 2026-09-23#

  • HTTP persistent connection, background read-ahead, seek window and breakpoint recovery; request headers and cache validators are retained with the request.
  • Supports Dolby Vision RPU reshaping and color conversion, covering Profile 5 / 8 and Profile 7 base layer mapping.
  • Default BT.2390 / IPT tone mapping, add more operators, target black point and contrast, and cached perceptual color gamut LUT.
  • HDR10 software frames use scene brightness statistics to adjust mapping, Apple EDR output follows monitor headroom.

0.1.8 · 2026-09-07バージョン#

Added HTTP opening options and pre-reading window configuration, unified SDK publishing entrance, and Windows Flutter SDR textures. Presenter configuration adds video alpha mode, and the native host needs to update the header files and runtime accordingly.

Transparent video with cross-platform native GPU compositing (#124)

  • Added packed-alpha video presentation (ErikaVideoAlphaMode.packedAlphaRight): Materials with left half color and right half alpha are reconstructed in GPU pre-multiplied by alpha and rendered at half the encoding width; players that do not request this mode behave unchanged.
  • macOS adds the Flutter Texture path of IOSurface + Metal (ErikaTextureVideoView), no frame-by-frame CPU readback to obtain Flutter opacity, cropping, transformation and color filters; switch to native when background-aware mixing is required CAMetalLayer(Support overlayBlendMode with layer opacity).
  • Windows transparent video is changed to DirectComposition synthesis: Composition Swap Chain pre-multiplied by alpha is directly bound to Flutter HWND, replacing the original independent opaque pop-up window; supported srcOver / overlay Blending and opacity, overlay can sample real game backgrounds within the same HWND. Opaque videos maintain the original HWND playback path.
  • The native playback speed limit has been increased from 4× to 16×, and accelerated playback of short animations and special effects materials is supported.
  • C ABI New erika_presenter_create_with_output_mode_and_alpha、erika_presenter_attach_flutter_texture / erika_presenter_set_flutter_texture_buffer with erika_presenter_windows_composition_swapchain_iunknown(AddRef/Release Proprietary).

Danmaku continuity and the JSON contract (#121)

  • Keep track allocation and admission decisions between consecutive planning sliding windows stable to prevent abandoned danmaku from reappearing midway or forcing visible danmaku to change tracks.
  • Decouple the danmaku service ID passed in by the host from the kernel's internal layout identity, and support parsing the optional JSON ID into precise u64 or decimal string to avoid ID truncation caused by floating point double precision rounding.
  • Formally standardize and document the inline danmaku JSON contract, supporting standard arrays and comments / danmaku / items root object.

0.1.6バージョン#

Rendering and playback

  • Added ArtCNN C4F16 DS noise reduction/sharpening brightness super-resolution, for degraded animation sources, through the Rust, C, Flutter, Metal and wgpu interfaces.
  • presenter rendering of Android and macOS moved out of the application UI / main thread; Android AHardwareBuffer conversion bandwidth reduced; D3D11 no longer multiplexes frames across devices.
  • The Apple platform selects SDR / EDR output according to the source content; the resource status is exposed through the integration of Android, Windows and OpenHarmony.

Integration and behavior

  • Danmaku scroll overwrite is turned off by default, keeping the stabilized danmaku from being overwritten during high-density playback.
  • Restored Windows system media control build; ArkTS declaration of OpenHarmony Flutter plug-in changed to explicit.

0.1.5バージョン#

System media control and background audio

  • Now Playing metadata, playback status, timeline, play / pause / seek and previous and next song navigation, covering six platforms: iOS, tvOS, macOS, Android, Windows, OpenHarmony.
  • Optional background audio playback for iOS and Android. Video decoding is suspended in the background, and the life cycle callback is queued by bounded barrier, which will not block the application thread indefinitely.
  • Not carried ErikaMediaMetadata Clear stale metadata when opening media; pause / play timing is finalized; Android media callbacks are isolated by Flutter engine.
  • Android cover image cache; media notifications will not be rebuilt when the native playback status has not changed.

Platform support and product release

  • tvOS plug-in and native target: real device and arm64 / x86_64 emulator, including Metal rendering, Apple audio, VideoToolbox, subtitles, danmaku, screenshots and HTTP source.
  • New erika-capi-tvos.zip(real machine + universal simulator xcframework), automatically add release workflow.
  • OpenHarmony optional precompiled consumption: CMake build downloadable tagged liberika_capi.so put on liberika_flutter.so Next, fail to roll back the source code build.
  • The CI and release of macOS / iOS / tvOS are unified to macOS 26 runner; macOS x64 and arm64 are cross-constructed and then synthesized into a common package. Zero-length HTTP resources are no longer misinterpreted as truncated.

Subtitle memory font

  • The memory subtitle font registry connects Rust, C, API, Dart with each native Flutter embed. The host can check the font faces, select the ordered fallback set, replace the font data, and clear the registry without writing to the disk.
  • libass preserves ordered rollback; TTC / OTC data is shared across face; when fonts in the same path are replaced, the renderer cache is invalidated and the active subtitle track uses the new data immediately.
  • Algebraic separation of registry and selected set; renderer rebuild to replay libass codec private data; OpenHarmony and tvOS to complete the full memory font C API surface.

Play resume

  • Enter explicit buffer conversion when audio and video input is hungry. The playback clock freezes during stall and is re-anchored to the media time after the data is restored to avoid overrunning the clock and causing long-term frame drops or black screens.

0.1.4バージョン#

Compatibility Tips

  • Danmaku outline_width Change to gears instead of multipliers.0 off, 1 fine, 2 normal, 3 coarse, over 3 clamp to coarse. Normal and coarse scales exactly reproduce the width of the old continuous multipliers at 1.0 and 2.0, so previously sent outline_width: 1.0 The host must now send 2.0 to keep the same stroke. Unmigrated strokes become thinner: the rasterization radius is halved from 2 px to 1 px at the default font size.
  • The danmaku font size is explained in pixels per em.ab_glyph of PxScale It is the height from ascender to descender. The old code directly passes in the em size, and the rendering is smaller than the request. The text is now consistent with the request, and the danmaku has become larger after the upgrade. The ratio of PingFang SC is 1.4, which is 40% larger for the same configuration. Hosts who want an older look should lower the font size.
  • The scrolling duration of the danmaku scales with the logical width of the viewport (×0.9 at 640 pt, ×1.3 at 1920 pt and above). The same configuration scrolls more slowly on large windows.
  • Danmaku screenshots no longer contain danmaku;capture_* Only video and subtitles are synthesized, debug HUD are not included in screenshots.

Platform support and product release

  • OpenHarmony playback backend and Flutter plug-in: AVCodec H.264 / HEVC hardware decoding, OHNativeBuffer / Vulkan zero-copy rendering, WGPU synthesis, subtitles, danmaku, audio, diagnosis and RGBA screenshots. publish erika-capi-openharmony-arm64.zip。
  • Windows ARM64 native dependencies and erika_capi build, add erika-capi-windows-arm64.zip。
  • macOS arm64 / x86_64 / universal Optional build and corresponding archive.
  • On Apple Silicon, Android source code construction is changed to use the general function that comes with NDK glslc. x86_64 product re-enables FFmpeg optimized assembly, and source code construction requires NASM.

Playback, rendering and window integration

  • The shared playback clock is published directly, and the frame snapshot atomic sampling time, state and generation are included. Danmaku, subtitles and rendering share the same time base.
  • Paused seek decodes and renders the preview frame, the media clock remains frozen. seek preroll, EOF, and seek pause and resume startup race conditions no longer produce clock rollback, worker idling, or long black frames.
  • The demux requirements for audio and video are separated, and audio backpressure no longer blocks video packet scanning. Switching or adding subtitles does not reset the audio and video demux selection.
  • macOS renders reconstructed as CVDisplayLink, slow frame merging, reset display link after screen change. Duplicate overlay attachment and GPU resource work reduction during window migration.
  • Desktop overlay API supports multiple FlutterView and secondary window. The player maintains surface, visibility, generational and aspect-fit state when migrating between host windows.
  • Windows D3D11 overlay lifecycle, non-blocking rendering and recovery seek handling improvements. Subtitles are synthesized within the video viewport, and the danmaku maintain the full-window viewport.

Danmaku and subtitles

  • Align danmaku collision boundaries with rasterized strokes, correct shadow/stroke/text ordering, stabilize track preferences, and limit high-density overlap to overflow tracks.
  • During asynchronous reflow, the old danmaku plan continues to move; pure drawing settings reuse the layout, and the visibility takes effect immediately.
  • Incremental glyph atlas is uploaded and reusable Metal instance buffer, reducing the DFM allocation and candidate traversal overhead per frame.
  • Character set detection and transcoding of plug-in text subtitles, covering GBK, Big5, Shift_JIS, UTF-16, UTF-8 pass-through, low confidence or binary input fallback protection.
  • libass is registered on all platforms. liberika is built-in. Droid Sans Fallback; the target of non-system font providers defaults to this family and no longer falls into the unparsable category. Arial。
  • Subtitle fallback and selective style overrides: custom font families and files, RGBA color, metrics, text properties, borders, alignment, margins, blur. The entrance is erika_presenter_set_subtitle_font、erika_presenter_set_subtitle_style with ErikaPlayer.setSubtitleStyle。

Network and Media Diagnostics

  • erika_open_with_headers with erika_presenter_open_with_headers. The request header is applied to probe, range reading, retrying and prefetching, but is not passed to subtitles and danmaku sidecar.
  • Reject the host's incoming liberika managed transport header and illegal HTTP field. HTTP range input hardening: ignored Range, error offset, transient failure, partial response, repeated prefetch with false EOF, retry bounded.
  • Track bitrate and rational frame rate metadata pass through Rust, C, Dart. Optional native debug HUD covers decoder, renderer, GPU, audio, output and HDR, danmaku diagnostics.

Audio, color and codecs

  • Surround to stereo downmix matrix normalization to prevent clipping.
  • Added callback volume ramping to all audio backends; WASAPI device loss recovery with observable recovery status and bounded backoff.
  • Metal, WGPU, D3D11 support BT.2100 HLG decoding; D3D11 overlay correctly encodes PQ on HDR10 output.
  • FFmpeg is upgraded to 8.1.2; Darwin AV1 hardware decoding import is improved; seek retains the last frame during loading and no longer flashes to black.
