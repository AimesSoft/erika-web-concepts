发布与产物

Releasing and Artifacts

release workflow 构建原生 erika_capi 与 Web / WASM 预编译产物并挂到 GitHub Release。每个 bundle 包含库文件、erika.h、MPL-2.0 许可证与依赖声明。桌面 Linux 暂不发布。

  • 平台 6 个原生 + Web
  • ZIP 归档 15 个
  • profile lgpl

触发トリガー#

推入 v* 标签触发正式发布，构建完成后发布到 GitHub Releases。workflow_dispatch 手动运行只构建不发布，用于发布前检查。发布前先在本机执行 构建流程 验证。

git tag v0.3.0
git push origin v0.3.0

标签前准备#

先把根 Cargo.toml 的 [workspace.package].version 改为目标版本，再执行 cargo update -w 并一同提交 Cargo.lock。CI 的 --locked 构建要求两者一致。保留 vendored 上游依赖的版本。

更新根目录、Flutter 与 OHPM 的 CHANGELOG 和安装文档，确认主分支 CI 通过，并完成 releasing 文档要求的格式、测试、clippy 和 Dart 发布检查。Release 在入口校验标签版本与 Cargo workspace 版本；不一致时立即失败。

Flutter、OHPM 与 Swift 的版本及原生摘要由后续工作流同步。GitHub Release 完成后，还需分别确认 pub.dev、SwiftPM 和 OHPM 的公开版本；OHPM 上传成功不等于审核完成。

Web / WASM 归档#

liberika-web-0.3.0.zip 由 cargo run -p xtask -- web build 生成，包含 JavaScript、两个 WASM、Worker、许可证、build-manifest.json 和 index.html 演示页。与原生 ZIP 一起写入 SHA256SUMS。

完整解压后通过 HTTPS 或 localhost 访问；独立静态部署即可选择本地 MKV 播放。Web 包尚未发布到 npm，接入及兼容范围见 Web 指南。

OpenHarmony OHPM 包OHPM パッケージ#

OpenHarmony arm64 的原生 ArkTS 包 erika 通过 OHPM 分发，最低兼容 API 18。截至 2026-10-30，0.3.0 已通过审核并公开可用：

shell

ohpm install erika@0.3.0

包内含 N-API bridge 与匹配的 liberika_capi.so，接口与 XComponent surface 生命周期见 OpenHarmony package guide。

bundle 结构構成#

C ABI bundle 由 packaging/bundle.sh 生成，结构一致：

<bundle-name>/
  lib/                    # 库文件或 xcframework
  include/erika.h         # C ABI 头文件
  LICENSE                 # MPL-2.0
  THIRD_PARTY_NOTICES.md  # 依赖许可证声明与 LGPL relink 说明
  licenses/               # 各依赖的许可证原文
  MANIFEST.txt            # ref / commit / profile / 构建时间

MANIFEST.txt 记录构建出处：bundle 名、git ref、commit、profile 与 UTC 时间。排查产物来源时先读它。

THIRD_PARTY_NOTICES.md 说明 LGPL 组件的 relink 义务：库以静态链接分发，改动态链接的宿主需要能替换这些组件。

预编译消费プレビルト利用#

Flutter 插件构建时默认下载预编译运行时（erika_flutter 的 pub.dev 版本自带校验与缓存）；需要从源码构建时显式导出：

export ERIKA_FORCE_SOURCE_BUILD=1    # 改为源码构建（需 ERIKA_REPO_ROOT 指向仓库检出）
export ERIKA_PREBUILT_TAG=v0.3.0       # 自定义预编译版本标签，默认匹配当前版本

显式覆盖 ERIKA_PREBUILT_TAG 时，必须同时设置与该归档匹配的 ERIKA_PREBUILT_SHA256；从同一 Release 的 SHA256SUMS 读取对应平台摘要。源码构建与自定义预编译版本是两种独立配置方式。

构建脚本按平台从 github.com/AimesSoft/liberika/releases/download/<tag>/ 下载对应 bundle 并解包，并按发布级 SHA256SUMS 校验摘要。

native 宿主的消费方式：把 bundle 解包，include/erika.h 作为唯一头文件，lib/ 内的库链接进宿主，见C ABI 嵌入。

构建与包发布流程#

当前 main 的 Release workflow 将 macOS 两个架构、iOS 三个 slice、tvOS 三个 slice、Android 四个 ABI、Windows 两个架构与 OpenHarmony 分开构建，完成后再合并 universal / XCFramework 或按 ABI 打包。原生依赖缓存按目标保存，CI 与 Release 复用。

发布共生成 15 个 ZIP：9 个 C ABI 归档、4 个按 ABI 拆分的 Flutter Android 运行时、1 个 Swift XCFramework，以及 1 个 Web / WASM 包。SHA256SUMS 记录全部归档摘要。

原生标签发布成功后，Release ecosystem packages 更新 Flutter / OHPM 版本及原生产物摘要，随后发布 pub.dev 与 OHPM；Swift XCFramework 构建及 SwiftPM 发布并行推进。OHPM 上传成功后仍需完成平台审核，公开版本以 registry 为准。

主分支 CI 按变更路径选择原生任务；旧分支构建可取消。仅改文档或生态包发布脚本时，主 CI 跳过原生构建；原生源码、依赖补丁和 CI / Release 构建脚本变更仍会触发。
