运行时模型ランタイム#

三个事实决定大多数改动的落点：

  • PresenterRuntime 拥有整个栈。 宿主每帧调 render_tick(time_seconds)；runtime 拉取解码帧、更新 overlay（字幕 + 弹幕）、渲染并呈现。弹幕 plan 以 generation + media_time 门控，与视频保持同步。
  • 音频是主时钟。 音频输出跑在自己的后端线程，播放调度器把视频呈现按 vsync 量化对齐到音频时钟。
  • 后端可插拔。 RendererBackend、AudioOutputBackend、DecoderBackend 三个 trait 使 presenter 保持平台无关。偏好经 RendererBackendPreference（PlatformNative / WgpuFallback）与 VideoDecodePreference 选择。

新增一个平台后端新規バックエンド#

新平台通常意味着三块，各自藏在 #[cfg(target_os = ...)] 之后：

  1. 解码。 在 DecoderBackend 里加变体，配置硬件设备（参考 D3D11VA 与 VideoToolbox 路径），产出渲染器可零拷贝导入的 PlayerVideoFrame。互操作不可用时回退软解。
  2. 渲染。 在 renderer/<backend>.rs 实现 RendererBackend：attach / detach / resize、upload_player_frame（拥有导入的 GPU 表示）、render_current_frame（合成 overlay），以及可选的 capture、runtime_stats、set_luma_upscaler。用 renderer::pipeline 做色彩与 tone-map 决策，行为与其它后端一致。D3D11 后端是最近的完整范例。
  3. 音频。 实现 AudioOutputBackend：configure / start / pause / stop / push / set_volume / state / stats，以及用于 A/V 同步的 clock_snapshot。复用 BufferedAudioOutput / AudioRingBuffer；WASAPI 是参考实现。

然后把后端接进 presenter 选择，并加一个 <platform>_native_demo 示例做端到端验证。

C ABI 是一份契约C ABI 契約#

erika_capi 是所有非 Rust 宿主的稳定接入面。改它时：

  • 把 panic 留在里面。 每个导出都把函数体包在 catch_unwind，panic 映射为 ErikaStatus_Panic。unwind 绝不穿越边界。
  • 尊重所有权。 交出的字符串归调用方所有，由配套 *_free 释放。
  • 同步 erika.h。 手动更新头文件以匹配，新函数带注释。
  • 同步 Swift 镜像结构体。 Apple 插件在 Swift 侧手写镜像 C 结构体（如 ErikaPresenterStats）。改了 erika.h 的结构体，必须同时更新 packages/erika_flutter 的两个 Swift 镜像文件。不匹配会破坏栈，可能表现为误导性的 autorelease-pool 崩溃。
  • 记录 JSON 方法。 presenter 的 JSON bridge 方法与 C 面一一对应，新增时要同步方法清单。

测试与验证テスト#

cargo test --workspace
cargo clippy --workspace
cargo fmt --all
  • 平台相关代码以 #[cfg] 门控。改某个分支时，保持 macOS / iOS / Windows / Android / fallback 各分支都能编译。本地测不了的目标交给 CI。
  • 神经超分权重在 tests/artcnn_upscaler.rs（Metal）与 tests/wgpu_artcnn.rs（分块 wgpu）中对照 onnxruntime 参考验证。修改 kernel 前必须重新核对对应路径。
  • Android SDR 播放与明确的 output fallback 已验证。API 35 HDR 真机 active path 通过 Rgba16Float + SCRGB_LINEAR 及恢复检查之前，不得把 extended-linear scRGB 标记为真机已验证。
  • 原生 demo 兼作冒烟测试：cargo run -p macos_native_demo -- --smoke-seconds 3 "$SAMPLE"（Windows 有等价命令）。它打印流水线计数器，用确认硬解与零拷贝互操作仍然生效。

约定規約#

  • Edition 2024，Rust 1.92+。跑 cargo fmt，保持 clippy 干净。
  • 热路径或跨 FFI 不 unwrap / panic。返回 Result，在边界映射为 ErikaStatus。
  • 与周围代码一致：命名、注释密度、既有的 cfg 结构。平台胶水留在平台模块里，别散进引擎。
  • 保持文档同步。用户可见的改动要反映到本套文档；基准语言为英文，翻译随后。
  • PR 保持聚焦。注明你构建与测试过的平台，以及留给 CI 的平台。
