トリガートリガー#

押し込む v* このタグは正式リリースをトリガーし、ビルドが完了した後、GitHub Releases にリリースされます。 workflow_dispatch 公開せずにビルドのみを手動で実行します。リリース前のチェックに使用されます。公開する前にローカルマシンで実行する ビルドプロセス 確認する。

git tag v0.3.0
git push origin v0.3.0

ラベルを貼る前の準備#

最初のルート Cargo.toml の [workspace.package].version 対象バージョンに変更して再度実行 cargo update -w そして一緒に提出してください Cargo.lock。 CIの --locked ビルドでは両方が一貫している必要があります。 vendored のバージョンのアップストリーム依存関係を保持します。

CHANGELOG と、ルート ディレクトリ Flutter および OHPM のインストール ドキュメントを更新し、メイン ブランチ CI が合格していることを確認し、releasing ドキュメントで必要なフォーマット、テスト、clippy および Dart のリリース チェックを完了します。 Release は入り口のタグのバージョンと Cargo workspace のバージョンをチェックします。矛盾がある場合はすぐに失敗します。

Flutter、OHPM、および Swift のバージョンとネイティブ サマリーは、後続のワークフローによって同期されます。 GitHub Release が完了したら、pub.dev、SwiftPM、OHPM の公開バージョンをそれぞれ確認する必要があります。 OHPM のアップロードが成功しても、レビューが完了したことを意味するものではありません。

Web / WASM アーカイブ#

liberika-web-0.3.0.zip によって cargo run -p xtask -- web build JavaScript、2 つの WASM、Worker、ライセンスを含む生成、build-manifest.json そして index.html デモページ。ネイティブ ZIP で書き込みます SHA256SUMS。

完全な解凍後、HTTPS または localhost を通じてアクセスします。独立した静的展開では、ローカルの MKV 再生を選択できます。 Web パッケージはまだ npm にリリースされていません。アクセスと互換性の範囲を参照してください。 Webガイド。

bundle構造構成する#

C ABI bundle によって packaging/bundle.sh 同じ構造で生成されます。

<bundle-name>/
  lib/                    # 库文件或 xcframework
  include/erika.h         # C ABI 头文件
  LICENSE                 # MPL-2.0
  THIRD_PARTY_NOTICES.md  # 依赖许可证声明与 LGPL relink 说明
  licenses/               # 各依赖的许可证原文
  MANIFEST.txt            # ref / commit / profile / 构建时间

MANIFEST.txt レコード構築ソース: bundle 名、git ref、commit、profile、UTC 時間。製品ソースのトラブルシューティングを行うときに、最初にお読みください。

THIRD_PARTY_NOTICES.md 説明 LGPL コンポーネントの relink 義務: ライブラリは静的リンクで配布されており、動的リンクを変更するホストはこれらのコンポーネントを置き換えることができる必要があります。

プリコンパイル済みの消費プレビルトの利用#

プリコンパイルされたランタイムは、Flutter プラグインのビルド時にデフォルトでダウンロードされます (erika_flutter pub.dev バージョンには検証とキャッシュが付属しています)。ソース コードからビルドする場合は、明示的にエクスポートする必要があります。

export ERIKA_FORCE_SOURCE_BUILD=1    # 改为源码构建（需 ERIKA_REPO_ROOT 指向仓库检出）
export ERIKA_PREBUILT_TAG=v0.3.0       # 自定义预编译版本标签，默认匹配当前版本

明示的なオーバーライド ERIKA_PREBUILT_TAG も設定する必要があります。 ERIKA_PREBUILT_SHA256;同じReleaseから SHA256SUMS 対応するプラットフォームの概要を読んでください。ソース コードのビルドとカスタム プリコンパイル バージョンは、2 つの独立した構成方法です。

プラットフォームごとにスクリプトを構築する github.com/AimesSoft/liberika/releases/download/<tag>/ 対応するbundleをダウンロードして解凍し、リリースレベルを押します SHA256SUMS 検証のまとめ。

native ホストの消費方法: bundle を解凍し、include/erika.h 唯一のヘッダー ファイルとして、lib/ ホスト内のライブラリをホストにリンクします。を参照してください。C ABI 埋め込み。

ビルドとパッケージのリリースのプロセス#

mainの現在のRelease workflowは、macOSの2つの構造、sliceの3つ、tvOSの3つ、slice、Androidの4つ、ABI、Windows、OpenHarmonyの構造を個別に構築し、完成後にそれらをマージします。 universal / XCFramework、または ABI としてパッケージ化されています。ネイティブ依存関係キャッシュはターゲットに従って保存され、CI と Release が再利用されます。

このリリースでは、合計 15 の ZIP が生成されました: 9 つの C ABI アーカイブ、ABI で分割された 4 つの Flutter Android ランタイム、1 つの Swift XCFramework、および 1 つの Web / WASM パッケージ。SHA256SUMS すべてのアーカイブの概要を記録します。

ネイティブ タグが正常に公開されると、Release ecosystem packages Flutter / OHPM バージョンとネイティブ製品概要を更新し、pub.dev および OHPM をリリースします。 Swift XCFrameworkの構築とSwiftPMのリリースは並行して進められます。 OHPM が正常にアップロードされた後も、プラットフォームのレビューを完了する必要があります。公開版はregistryに従うものとします。

メイン ブランチ CI は、変更パスに従ってネイティブ タスクを選択します。古いブランチのビルドはキャンセルできます。ドキュメントまたはエコロジカル パッケージ リリース スクリプトのみが変更された場合、メインの CI はネイティブ ビルドをスキップします。ネイティブ ソース コード、依存関係パッチ、および CI / Release ビルド スクリプトへの変更は引き続きトリガーされます。
