ランタイムモデルランタイム#

ほとんどの変更がどこで行われるかは、次の 3 つの事実によって決まります。

  • PresenterRuntime はスタック全体を所有します。 ホストはフレームごとに調整します render_tick(time_seconds); runtime はデコードされたフレームを取得し、overlay (字幕 + 弾幕) を更新し、レンダリングして表示します。弾幕 plan は generation + media_time でゲートされ、ビデオとの同期を維持します。
  • オーディオがマスタークロックです。 オーディオ出力は独自のバックエンド スレッドで実行され、再生スケジューラは vsync 量子化に従ってビデオ プレゼンテーションをオーディオ クロックに合わせます。
  • バックエンドはプラグイン可能です。 RendererBackend、AudioOutputBackend、DecoderBackend 3 つの trait により、presenter はプラットフォームに依存しません。好み RendererBackendPreference(PlatformNative/WgpuFallback) VideoDecodePreference 選ぶ。

新しいプラットフォーム バックエンドを追加する新規制バックエンド#

新しいプラットフォームは通常 3 つの部分を意味し、それぞれが隠されています。 #[cfg(target_os = ...)] 後:

  1. デコードします。 で DecoderBackend Riga バリアントでは、ハードウェア デバイスを構成し (D3D11VA および VideoToolbox パスを参照)、出力レンダラーはゼロ コピーでインポートできます。 PlayerVideoFrame。相互運用性が利用できない場合は、ソフト ソリューションにフォールバックします。
  2. レンダリングします。 で renderer/<backend>.rs 気づく RendererBackend：attach / detach / resize、upload_player_frame(GPU 表現をインポートしました)、render_current_frame(合成 overlay)、およびオプションで capture、runtime_stats、set_luma_upscaler。使う renderer::pipeline tone-map で色の決定を行い、他のバックエンドと一貫して動作します。 D3D11 バックエンドは、最新の完全な例です。
  3. オーディオ。 気づく AudioOutputBackend: configure / start / pause / stop / push / set_volume / state / stats、および A/V 同期用 clock_snapshot。再利用 BufferedAudioOutput / AudioRingBuffer;WASAPI はリファレンス実装です。

次に、バックエンドを presenter 選択に接続し、 <platform>_native_demo エンドツーエンド検証の例。

C ABI は契約ですC ABI 契約#

erika_capi これは、Rust 以外のすべてのホストにとって安定したアクセス サーフェスです。変更する場合:

  • panic はそのままにしておきます。 各エクスポートでは関数本体がラップされます。 catch_unwind、panic はにマッピングされます。 ErikaStatus_Panic。 unwind 決して国境を越えないでください。
  • 所有権を尊重します。 渡された文字列は呼び出し元に属し、一致する文字列によってサポートされます。 *_free リリース。
  • 同期する erika.h。 新しい関数に注釈を付けて、ヘッダー ファイルを手動で更新して一致させます。
  • Swift ミラー構造を同期します。 Apple プラグインは、Swift 側の C 構造をミラーリングします (たとえば、 ErikaPresenterStats）。変更されました erika.h 構造も同時に更新する必要があります packages/erika_flutter 2 つの Swift 画像ファイル。不一致によりスタックが破損し、誤解を招く autorelease-pool クラッシュとして現れる可能性があります。
  • JSON メソッドを文書化します。 presenter の JSON bridge メソッドは、C サーフェスに 1 対 1 で対応し、追加時に同期する必要があります。メソッドリスト。

テストと検証テスト#

cargo test --workspace
cargo clippy --workspace
cargo fmt --all
  • プラットフォーム関連のコードは次で始まります #[cfg] ゲーティング。特定のブランチを変更する場合、macOS / iOS / Windows / Android / fallback を保持すると、すべてのブランチをコンパイルできます。ローカルで測定できないターゲットは CI に与えられます。
  • ニューラルスーパースコアの重み付け tests/artcnn_upscaler.rs(Metal) 付き tests/wgpu_artcnn.rs(wgpu はブロックされています) onnxruntime リファレンスに対して検証されました。 kernel を変更する前に、対応するパスを再確認する必要があります。
  • Android SDR はクリア output fallback で再生確認済み。 API 35 HDR 実機 active path 合格 Rgba16Float + SCRGB_LINEAR extended-linear scRGB は、検査を再開する前に実機検証済みとしてマークされてはなりません。
  • ネイティブ demo はスモーク テストとしても機能します。cargo run -p macos_native_demo -- --smoke-seconds 3 "$SAMPLE"(Windows には同等のコマンドがあります)。パイプライン カウンターを出力します。これは、ハード デコードとゼロコピー相互運用性が引き続き機能することを確認するために使用されます。

同意書法令#

  • Edition 2024、Rust 1.92+。走る cargo fmt、clippyをきれいに保ちます。
  • ホットパスまたはFFIを越えていない unwrap / panic。戻る Result、境界マップは ErikaStatus。
  • 周囲のコードとの一貫性: 名前付け、コメント密度、既存のコード cfg 構造。プラットフォーム接着剤はプラットフォームモジュール内に残り、エンジンには入りません。
  • ドキュメントの同期を保ちます。ユーザーに表示される変更は、このドキュメント セットに反映されています。基本言語は英語であり、翻訳が続きます。
  • PR 集中してください。構築およびテストしたプラットフォームと、CI に残したプラットフォームを示します。
