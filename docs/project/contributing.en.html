runtime modelランタイム#

Three facts determine where most changes will be made:

  • PresenterRuntime owns the entire stack. Host adjusts every frame render_tick(time_seconds); runtime pulls the decoded frame, updates overlay (subtitles + danmaku), renders and presents. The danmaku plan is gated with generation + media_time to keep synchronized with the video.
  • Audio is the master clock. The audio output runs in its own backend thread, and the playback scheduler aligns the video presentation to the audio clock according to vsync quantization.
  • The back end is pluggable. RendererBackend、AudioOutputBackend、DecoderBackend Three trait make presenter remain platform independent. preference RendererBackendPreference(PlatformNative/WgpuFallback) with VideoDecodePreference choose.

Add a new platform backendNew regulations バックエンド#

The new platform usually means three pieces, each hidden in #[cfg(target_os = ...)] After:

  1. Decode. in DecoderBackend Riga variant, configure the hardware device (refer to D3D11VA and VideoToolbox paths), and the output renderer can be imported with zero copy PlayerVideoFrame. Fallback to software decoding when interop is not available.
  2. render. in renderer/<backend>.rs realize RendererBackend：attach / detach / resize、upload_player_frame(has imported GPU representation),render_current_frame(Synthetic overlay), and optionally capture, runtime_stats, set_luma_upscaler. use renderer::pipeline Makes color decisions with tone-map and behaves consistent with other backends. The D3D11 backend is the most recent complete example.
  3. Audio. realize AudioOutputBackend: configure / start / pause / stop / push / set_volume / state / stats, and for A/V synchronization clock_snapshot. Reuse BufferedAudioOutput / AudioRingBuffer;WASAPI is the reference implementation.

Then connect the backend to the presenter selection and add a <platform>_native_demo Example of end-to-end verification.

C ABI is a contractC ABI Contract#

erika_capi It is a stable access surface for all non-Rust hosts. When changing it:

  • Leave panic inside. Each export wraps the function body in catch_unwind, panic is mapped to ErikaStatus_Panic. unwind Never cross borders.
  • Respect ownership. The handed-over string belongs to the caller and is supported by the matching *_free release.
  • sync erika.h。 Manually update the header file to match, with new functions annotated.
  • Synchronize the Swift mirror structure. The Apple plug-in mirrors the C structure on the Swift side (such as ErikaPresenterStats). Changed erika.h The structure must be updated at the same time packages/erika_flutter Two Swift image files. A mismatch corrupts the stack, possibly manifesting as a misleading autorelease-pool crash.
  • Document the JSON method. The JSON bridge method of presenter corresponds to the C surface one-to-one, and must be synchronized when addingmethod list。

Testing and Validationテスト#

cargo test --workspace
cargo clippy --workspace
cargo fmt --all
  • Platform related code starts with #[cfg] Gating. When changing a certain branch, keep macOS / iOS / Windows / Android / fallback and all branches can be compiled. Targets that cannot be measured locally are given to CI.
  • Neural upscaling weight in tests/artcnn_upscaler.rs(Metal) with tests/wgpu_artcnn.rs(Blocked wgpu) Verified against onnxruntime reference. The corresponding path must be rechecked before modifying kernel.
  • Android SDR plays with the clear output fallback verified. API 35 HDR real machine active path passed Rgba16Float + SCRGB_LINEAR extended-linear scRGB must not be marked as real machine verified before resuming the inspection.
  • Native demo doubles as a smoke test:cargo run -p macos_native_demo -- --smoke-seconds 3 "$SAMPLE"(Windows has equivalent commands). It prints the pipeline counter, used to confirm that hardware decoding and zero-copy interop still work.

AgreementStatute#

  • Edition 2024, Rust 1.92+. run cargo fmt, keep clippy clean.
  • hot path or across FFI not unwrap / panic. return Result, the boundary map is ErikaStatus。
  • Consistent with surrounding code: naming, comment density, existing cfg structure. The platform glue remains in the platform module and does not get into the engine.
  • Keep documents in sync. User-visible changes are reflected in this set of documentation; the base language is English, with translations to follow.
  • PR Stay focused. Indicate the platforms you built and tested on, and the ones left for CI.
