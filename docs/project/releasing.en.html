Preparation before labeling#

first root Cargo.toml of [workspace.package].version Change to the target version and execute again cargo update -w and submit together Cargo.lock. CI of --locked The build requires both to be consistent. Keep the version of vendored upstream dependency.

Update the CHANGELOG and installation documentation of the root directory, Flutter and OHPM, confirm that the main branch CI passes, and complete the formatting, testing, clippy and Dart release checks required by the releasing documentation. Release checks the tag version at the entrance and Cargo workspace version; fails immediately if they are inconsistent.

The versions and native summaries of Flutter, OHPM and Swift are synchronized by subsequent workflows. After GitHub Release is completed, the public versions of pub.dev, SwiftPM and OHPM need to be confirmed respectively; the successful upload of OHPM does not mean that the review is completed.

bundle structureconstitute#

C ABI bundle by packaging/bundle.sh Generated with the same structure:

<bundle-name>/
  lib/                    # 库文件或 xcframework
  include/erika.h         # C ABI 头文件
  LICENSE                 # MPL-2.0
  THIRD_PARTY_NOTICES.md  # 依赖许可证声明与 LGPL relink 说明
  licenses/               # 各依赖的许可证原文
  MANIFEST.txt            # ref / commit / profile / 构建时间

MANIFEST.txt record construction source: bundle name, git ref, commit, profile and UTC time. Read it first when troubleshooting product sources.

THIRD_PARTY_NOTICES.md Description relink obligations of LGPL components: The library is distributed with static linking, and the host that changes the dynamic linking needs to be able to replace these components.

Precompiled consumptionUse of プレビルト#

The precompiled runtime is downloaded by default when the Flutter plug-in is built (erika_flutter The pub.dev version comes with verification and caching); it needs to be explicitly exported when building from source code:

export ERIKA_FORCE_SOURCE_BUILD=1    # 改为源码构建（需 ERIKA_REPO_ROOT 指向仓库检出）
export ERIKA_PREBUILT_TAG=v0.3.0       # 自定义预编译版本标签，默认匹配当前版本

Explicit override ERIKA_PREBUILT_TAG , you must also set the ERIKA_PREBUILT_SHA256;From the same Release SHA256SUMS Read the corresponding platform summary. Source code build and custom precompiled version are two independent configuration methods.

Build scripts by platform from github.com/AimesSoft/liberika/releases/download/<tag>/ Download the corresponding bundle and unpack it, and press the release level SHA256SUMS Verification summary.

Consumption method of native host: Unpack bundle,include/erika.h As the only header file,lib/ Link the library within the host into the host, seeC ABI embedded。

Build and package release process#

The current Release workflow of main will build two structures of macOS, three slice, tvOS three, slice, Android four, ABI, Windows and OpenHarmony separately, and then merge them after completion. universal / XCFramework or packaged as ABI. The native dependency cache is saved according to the target, and CI and Release are reused.

The release generated a total of 15 ZIP: 9 C ABI archives, 4 Flutter Android runtimes split by ABI, 1 Swift XCFramework, and 1 Web / WASM package.SHA256SUMS Record all archive summaries.

After the native tag is successfully published,Release ecosystem packages Update the Flutter / OHPM version and native product summary, and then release pub.dev and OHPM; Swift XCFramework construction and SwiftPM release are promoted in parallel. After OHPM is successfully uploaded, it still needs to complete the platform review. The public version shall be subject to registry.

The main branch CI selects native tasks according to the change path; the old branch build can be cancelled. When only the documentation or ecological package release script is changed, the main CI will skip the native build; changes to the native source code, dependency patches, and CI / Release build scripts will still be triggered.
