更新日志

Changelog

按版本列出对宿主可见的变化。已回退的条目不在此列；完整历史以仓库根 CHANGELOG.md 为准。0.1.3 及更早的 breaking change 见文末小结。

  • 当前 0.2.1
  • 发布 2026-10-02

0.2.1 · 2026-10-02#

  • HTTP 连接、TLS、响应读取与后台预读可取消；stop / close / 重新打开会回收网络线程及缓存，减少退出卡顿和资源残留。
  • Flutter、Swift 与 OpenHarmony SDK 可通过 httpBackBufferBytes 调整回退缓存，默认 16 MiB。
  • 补齐 WMV / WMA、dav1d 8-bit / 10-bit AV1 软件回退，以及 Windows 软件帧上传。
  • iOS 根据显示目标时刻调度视频、字幕和弹幕，并合并积压的渲染回调。
  • 新增实验性 Linux 支持：X11 / Wayland、PulseAudio、NVDEC / VA-API、Flutter 纹理及 Wayland 原生视频层。
  • P010 上传保留 10-bit 精度，改善 HDR 色彩转换。

0.2.0 · 2026-09-23#

  • HTTP 持久连接、后台预读、seek 窗口与断点恢复；请求头和缓存验证器随请求保留。
  • 支持 Dolby Vision RPU reshaping 与色彩转换，覆盖 Profile 5 / 8 及 Profile 7 基础层映射。
  • 默认 BT.2390 / IPT tone mapping，加入更多算子、目标黑点和对比度，以及缓存的感知色域 LUT。
  • HDR10 软件帧使用场景亮度统计调整映射，Apple EDR 输出跟随显示器 headroom。

0.1.8 · 2026-09-07バージョン#

新增 HTTP 打开选项与预读窗口配置、统一 SDK 发布入口，以及 Windows Flutter SDR 纹理。Presenter 配置加入视频 alpha 模式，原生宿主需要配套更新头文件与运行时。

透明视频与跨平台原生 GPU 合成 (#124)

  • 新增 packed-alpha 视频呈现（ErikaVideoAlphaMode.packedAlphaRight）：左半颜色、右半 alpha 的素材在 GPU 中重建预乘 alpha，按编码宽度的一半呈现；未请求该模式的播放器行为不变。
  • macOS 新增 IOSurface + Metal 的 Flutter Texture 路径（ErikaTextureVideoView），无逐帧 CPU 回读即可获得 Flutter 不透明度、裁剪、变换与颜色滤镜；需要背景感知混合时切换到原生 CAMetalLayer（支持 overlayBlendMode 与图层不透明度）。
  • Windows 透明视频改走 DirectComposition 合成：预乘 alpha 的 Composition Swap Chain 直接绑定 Flutter HWND，替代原独立不透明弹窗；支持 srcOver / overlay 混合与不透明度，overlay 可采样同一 HWND 内的真实游戏背景。不透明视频保持原有 HWND 播放路径。
  • 原生播放倍速上限从 4× 提升至 16×，支持短动画与特效素材加速播放。
  • C ABI 新增 erika_presenter_create_with_output_mode_and_alpha、erika_presenter_attach_flutter_texture / erika_presenter_set_flutter_texture_buffer 与 erika_presenter_windows_composition_swapchain_iunknown（AddRef/Release 所有权）。

弹幕连贯性与 JSON 契约 (#121)

  • 保持连续规划滑窗间的轨道分配与准入决定稳定，防止已丢弃弹幕中途重现或迫使可见弹幕换轨。
  • 将宿主传入的弹幕业务 ID 与内核内部布局身份解耦，支持将可选的 JSON ID 解析为精确 u64 或十进制字符串，避免浮点双精度舍入导致 ID 截断。
  • 正式规范并文档化内联弹幕 JSON 契约，支持标准数组与 comments / danmaku / items 根对象。

0.1.7バージョン#

Flutter 包发布

  • erika_flutter 首次发布到 pub.dev，包内附许可证、changelog、metadata、示例与独立测试。
  • 已验证并锁定版本的原生 bundle 成为 Android、Apple、Windows 与 OpenHarmony 的默认构建方式；需要源码构建时显式设置 ERIKA_FORCE_SOURCE_BUILD=1。
  • Android 按 ABI 拆分运行时归档：应用构建只下载所需架构，不再附带 native-embedder 静态库。
  • 每个发布新增覆盖全部原生归档的 SHA256SUMS 清单。
  • 六个平台各自的 GitHub Actions 消费构建独立化，package 构建不再依赖 monorepo。

OpenHarmony 原生包发布

  • 新增 OpenHarmony ArkTS / OHPM 包 erika，面向 arm64、API 18+。
  • 提供 XComponent surface 生命周期、播放控制、renderTick() 帧调度、事件与截图 API，并补充独立接入指南。

0.1.6バージョン#

渲染与播放

  • 新增 ArtCNN C4F16 DS 降噪 / 锐化亮度超分，面向劣化动漫片源，贯通 Rust、C、Flutter、Metal 与 wgpu 接口。
  • Android 与 macOS 的 presenter 渲染移出应用 UI / main 线程；Android AHardwareBuffer 转换带宽降低；D3D11 不再跨设备复用帧。
  • Apple 平台按源内容选择 SDR / EDR 输出；资源状态通过 Android、Windows 与 OpenHarmony 集成暴露。

集成与行为

  • 弹幕 scroll overwrite 默认关闭，高密度播放时保持已稳定的弹幕不被覆盖。
  • 恢复 Windows 系统媒体控制构建；OpenHarmony Flutter 插件的 ArkTS 声明改为显式。

0.1.5バージョン#

系统媒体控制与后台音频

  • Now Playing 元数据、播放状态、时间线、play / pause / seek 与上一首下一首导航，覆盖 iOS、tvOS、macOS、Android、Windows、OpenHarmony 六平台。
  • iOS 与 Android 的可选后台音频播放。后台时挂起视频解码，生命周期回调经有界 barrier 排队，不会无限阻塞应用线程。
  • 未携带 ErikaMediaMetadata 打开媒体时清除陈旧元数据；pause / play 时序确定化；Android 媒体回调按 Flutter engine 隔离。
  • Android 封面图缓存；原生播放状态未变化时不重建媒体通知。

平台支持与发布产物

  • tvOS 插件与 native target：真机与 arm64 / x86_64 模拟器，含 Metal 呈现、Apple 音频、VideoToolbox、字幕、弹幕、截图与 HTTP 源。
  • 新增 erika-capi-tvos.zip（真机 + 通用模拟器 xcframework），自动加入 release workflow。
  • OpenHarmony 可选预编译消费：CMake 构建可下载带标签的 liberika_capi.so 放在 liberika_flutter.so 旁，失败回退源码构建。
  • macOS / iOS / tvOS 的 CI 与发布统一到 macOS 26 runner；macOS x64 与 arm64 交叉构建后合成通用包。零长度 HTTP 资源不再误判为截断。

字幕内存字体

  • 内存字幕字体注册表贯通 Rust、C API、Dart 与各原生 Flutter 嵌入。宿主可检查字体 faces、选择有序回退集合、替换字体数据、清空注册表，全程不写盘。
  • libass 保留有序回退；TTC / OTC 数据跨 face 共享；同路径字体被替换时渲染器缓存失效，活跃字幕轨立即使用新数据。
  • 注册表与选中集合的代数分离；渲染器重建后重放 libass codec private data；OpenHarmony 与 tvOS 补齐完整内存字体 C API 面。

播放恢复

  • 音视频输入饥饿时进入显式缓冲转换。stall 期间播放时钟冻结，数据恢复后重锚定到媒体时间，避免时钟跑过头造成长时间掉帧或黑屏。

0.1.4バージョン#

兼容性提示

  • 弹幕 outline_width 改为档位而非乘数。0 关闭、1 细、2 普通、3 粗，超过 3 钳制为粗。普通与粗档精确复现旧连续乘数在 1.0 与 2.0 时的宽度，因此以前发送 outline_width: 1.0 的宿主现在必须发送 2.0 才能保持相同描边。未迁移的描边会变细：默认字号下光栅化半径从 2 px 减半为 1 px。
  • 弹幕字号按像素每 em 解释。ab_glyph 的 PxScale 是 ascender 到 descender 的高度，旧代码把 em 尺寸直接传入，渲染比请求小。现在文字与请求一致，升级后弹幕变大。PingFang SC 的比例是 1.4，同一配置可大 40%。想要旧外观的宿主应调低字号。
  • 弹幕滚动时长随视口逻辑宽度缩放（640 pt 时 ×0.9，1920 pt 及以上 ×1.3）。同一配置在大窗口上滚动得更慢。
  • 弹幕截图不再包含弹幕；capture_* 只合成视频与字幕，debug HUD 也不入截图。

平台支持与发布产物

  • OpenHarmony 播放后端与 Flutter 插件：AVCodec H.264 / HEVC 硬解、OHNativeBuffer / Vulkan 零拷贝呈现、WGPU 合成、字幕、弹幕、音频、诊断与 RGBA 截图。发布 erika-capi-openharmony-arm64.zip。
  • Windows ARM64 原生依赖与 erika_capi 构建，新增 erika-capi-windows-arm64.zip。
  • macOS arm64 / x86_64 / universal 可选构建与对应归档。
  • Apple Silicon 上 Android 源码构建改用 NDK 自带的通用 glslc。x86_64 产物重新启用 FFmpeg 优化汇编，源码构建需要 NASM。

播放、渲染与窗口集成

  • 共享播放时钟直接发布，帧快照原子采样时间、状态与代数。弹幕、字幕与渲染共用同一时间基。
  • 暂停中 seek 解码并呈现预览帧，媒体时钟保持冻结。seek preroll、EOF、紧随 seek 的暂停与恢复启动竞态不再产生时钟回滚、worker 空转或长时间黑帧。
  • 音频与视频的 demux 需求分离，音频背压不再阻塞视频包扫描。切换或添加字幕不重置音视频 demux 选择。
  • macOS 呈现重构为 CVDisplayLink，慢帧合并，屏幕变化后重设 display link。resize 与窗口迁移期间的重复 overlay 附着与 GPU 资源工作减少。
  • 桌面 overlay API 支持多 FlutterView 与次窗口。播放器在宿主窗口间迁移时保持表面、可见性、代际与 aspect-fit 状态。
  • Windows D3D11 overlay 生命周期、非阻塞呈现与恢复 seek 处理改进。字幕在视频视口内合成，弹幕保持全窗口视口。

弹幕与字幕

  • 弹幕碰撞边界与光栅化描边对齐，修正阴影 / 描边 / 文字层序，稳定轨道偏好，高密度重叠限制在溢出轨。
  • 异步重排期间旧弹幕 plan 继续移动；纯绘制设置复用布局，可见性即时生效。
  • 增量 glyph atlas 上传与可复用 Metal instance buffer，减少每帧 DFM 分配与候选遍历开销。
  • 外挂文本字幕的字符集检测与转码，覆盖 GBK、Big5、Shift_JIS、UTF-16，UTF-8 直通，低置信度或二进制输入回退保护。
  • libass 全平台注册 Erika 内置 Droid Sans Fallback；无系统字体提供者的目标默认该族，不再落到不可解析的 Arial。
  • 字幕回退与选择性样式覆盖：自定义字体族与文件、RGBA 颜色、度量、文本属性、边框、对齐、边距、模糊。入口为 erika_presenter_set_subtitle_font、erika_presenter_set_subtitle_style 与 ErikaPlayer.setSubtitleStyle。

网络与媒体诊断

  • erika_open_with_headers 与 erika_presenter_open_with_headers。请求头应用到 probe、range 读、重试与预取，但不传给字幕与弹幕 sidecar。
  • 拒绝宿主传入 Erika 管理的传输头与非法 HTTP 字段。HTTP range 输入加固：被忽略的 Range、错误偏移、瞬时失败、部分响应、重复预取与假 EOF，重试有界。
  • 轨道 bitrate 与有理帧率元数据贯通 Rust、C、Dart。可选原生 debug HUD 覆盖解码器、渲染器、GPU、音频、输出与 HDR、弹幕诊断。

音频、色彩与编解码

  • 环绕到立体声降混矩阵归一化，防止削波。
  • 全部音频后端加入逐回调音量斜坡；WASAPI 设备丢失恢复带可观测恢复状态与有界退避。
  • Metal、WGPU、D3D11 支持 BT.2100 HLG 解码；D3D11 overlay 在 HDR10 输出上正确编码 PQ。
  • FFmpeg 升至 8.1.2；Darwin AV1 硬解导入改进；seek 加载期间保留最后一帧，不再闪黑。

0.1.3 及更早以前#

0.1.3 引入 Android 完整播放路径（MediaCodec、AHardwareBuffer / wgpu、AAudio、PlatformView、字幕、弹幕、截图、SDR / HDR）。其中两条 breaking change 至今有效：

  • 表面尺寸语义。 attach 与 resize 的 width / height 表示物理像素的精确 drawable 尺寸，不再乘以 scale。scale 只影响弹幕等逻辑 UI 内容。
  • play 异步化。 play 排队执行，不再等待播放 worker。最终结果以 StateChanged 与 Error 事件为准。
